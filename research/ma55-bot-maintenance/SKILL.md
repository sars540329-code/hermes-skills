# 55MA 機器人維護與選股訊號校準

機器人在 `E:\XQOWL\55MA機器人\`（`ma55_breakout_bot.py`，版本在檔頭註解；網頁 `黃金潮汐海島.html` 讀 `report_data.js`）。更新海島／查今日資料用 `golden-tide-island`；規則定義（蕭明道體系）用 `ma55-main-rise`；本 skill 管「改程式、加訊號、重跑」。

## 執行環境
- Python：Student package 的 `.venv\Scripts\python.exe`（3.13）。路徑含空格與括號，bash 先 `SP=".../Student package"; PY="$SP/.venv/Scripts/python.exe"` 再引用變數，否則被拆壞。
- 背景重跑用 terminal `background=true`，命令內不加 `&`；殺程序 `taskkill /PID <pid> /F`（git-bash 的 `//PID` 會失敗）。
- 手動盤後：`"$PY" -X utf8 ma55_breakout_bot.py --night > logs/bot_YYYYMMDD_tag.log 2>&1`；完成訊號＝log 出現「網頁資料已更新」。
- 確認有沒有更新：看最新 `logs/bot_*.log` 尾端「網頁資料已更新（日期）」＋`data_55ma/web_picks_today.json` 的 `date` 與 rows 數。`report_data.js` 頂層是**以日期為鍵**的 dict（`data['2026-10-15']['picks']`），不是扁平物件——直接讀 `data['picks']` 會得到 0 而誤判沒更新；picks 的 `code` 欄位常是 None，認名用 `name`。
- 價格 CSV：`Student package\data_yf\<代號>.csv`（date/open/high/low/close/volume；volume 單位股，1 張＝1000 股）。用 `importlib` 載入 bot（有 `__main__` 保護）直接呼叫 `weekly_from_daily`、`evaluate`、各 `sig_*`，預覽不需等 FinMind。
- 驗證腳本加 `python -W ignore`，迴圈跑全市場時避免 DeprecationWarning 洗版。

## 改程式硬規則
- 先備份 `.bak_vXXX`；改完 `ast.parse` 語法檢查；檔頭註解升版並同步啟動訊息版本號。
- 同日重跑 `--night` 不會清當日紀錄：`data_55ma/web_picks_today.json` 與 `panstate_track.json` 會殘留先前跑次／舊條件的結果（盤後掃描開頭已加重設）。改過篩選條件後重跑，要核對這兩檔當日筆數＝新 log 命中數，否則網頁與明日「追蹤第N天」被污染。
- FinMind 額度（600 次/小時）耗盡時機器人每 10 分鐘重試最多 6 次，`taiex_above_55ma` 預設放行；選股計算不依賴 FinMind，只有網頁豐富資料會卡。要預覽結果直接用本機 `evaluate()`，不要乾等（約 1 小時恢復）。
- 成交量門檻 `VOL_MIN`（張）套在多個過濾點，改值要全部確認。凹洞量類訊號另需近 5 日外資+投信買超 > 0；上櫃查不到法人 → 保守不顯示。
- Telegram 單則上限 4096 字。`send_telegram_text` 已內建依行切段（3800 字上限、每段標 k/n）。測切段時把 `requests.post`／`resolve_chat_id`／`log_notification` 換成 mock，驗證「拼回原文相等、`<b>`／`<i>` 標籤不被切斷、單段＋標註後 ≤4096」三件事，不要真的打 API 測。
- 排程 `MA55_Night_2145` 以 `schtasks /Query` 驗證實際下次時間，不只信 bat 內容。中文 Windows 的輸出「下午 09:45:00」就是 21:45，別誤讀成上午；`schtasks` 中文輸出要以 cp950 解碼，grep 英文關鍵字會查不到。

## 加新選股訊號：用標準例截圖校準
1. 先從截圖右側資訊框讀出游標那根的日期與收盤，和 CSV 對照；價位對不上＝日期搞錯，先查清楚不要硬測。週K 以 W-FRI 重取樣，標籤是該週週五（使用者說「1/19 那根」＝含 1/19 的那一週，標籤 1/23）。
2. 「游標那根」＝含當日的當週K（進行中週K），不是上一根完整週；「前一根」只套用在使用者指定的那一條（如乖離）。兩者不可互換。
3. 週線條件全部用週K；日線參數不能直接搬到週K。使用者口中的「3盤」是**寶塔**定義（當根收盤 > 2根前高點＋出量），不是日線那套「3 根窄幅量縮」——先問清定義再寫碼，用窄幅高低差會抓不到他的標準例。指標算法一律對齊使用者查價框看到的 XQ 定義（週21MA 是 SMA，EMA 只用於 8；XQ 免費版沒有 EMA 乖離），不要為了讓標準例命中而偷偷換算法——換算法只是把門檻對到自己的錯值上。
4. 對每個標準例日期逐條件印「✅/❌＋實際值 vs 門檻」表，找出卡哪條再決定放寬。使用者明確給的數字（如乖離 <15%）不動；只調沒指定數字的參數，並在回報列出自己調過的值。
5. 標準例要全部命中（常給同一檔的 2 個以上波段），並檢查相鄰日期不會錯位誤抓。
6. 命中後全市場（量≥5000張）掃目標日與今日，回報檔數與名單；合理命中率約 2~3%，過高代表門檻太鬆（金融股波動小，百分比窄幅門檻易失效）。
7. 回報註明：只在檔案內測過、尚未 `--night`（網頁看不到）；未做勝率回測與隨機對照；標準例是事後挑選的贏家。使用者要策略結果時必須實跑勝率（全部／已出場／持有中）。
8. 使用者的 clarify 問題常沒有回應（回空）；改給一句可直接複製的選項，或先用最合理解讀實作並列出假設，不要連問多輪。
9. 截圖若裝在 .pptx／.zip 裡，先用 `zipfile` 把 `ppt/media/*` 取出（副檔名可能是 `.tmp`，存檔時改成 `.png`），再 `vision_analyze` 逐張讀圖。同一批圖讀不出來時換路徑再試一次，不要重送同一個失敗的呼叫。

## 回測腳本與網頁發布
- 週線回測 `backtest_weekly_mainrise.py`：訊號要先「同檔 4 週內只取第一次」再「每週取量最大前 3 檔」，才貼近本金 100 萬同時 1~3 檔；未去重的筆數會灌水。隨機對照用同週同數量抽樣。輸出存 `logs/backtest_wmr_*.log`。
- 改這類大腳本用 `patch` 分段改；`write_file` 覆寫前若只用 offset/limit 讀過會被擋，要整檔讀完或改用 patch，別重送同一個失敗的呼叫。若剛讀完整檔仍被擋（記錄誤判成部分讀取），改走 `mv 檔 .old` → 寫入新檔 → 用 search_files 驗證 → `rm .old`，不要用 patch 硬湊整份長文件。
- 網頁（`黃金潮汐海島.html` + `report_data.js`）直接雙擊開會被 file:// 擋載入 js，要在該資料夾 `python -m http.server 8766`（background）再開 `http://localhost:8766/...`；只有本機能開。`report_data.js` 只有公開行情與選股，無金鑰。
- 想給自己手機／外部看：GitHub Pages 免費版需公開倉庫；僅自己可看的免費做法是 Cloudflare Pages + Access（Email 驗證碼）或 Tailscale。`npx wrangler login` 要用背景程序保持 localhost:8976 回呼，並請使用者在已登入的瀏覽器開授權網址。

## 週線主升段回測凹洞（v3.7.0，`sig_weekly_mainrise`）
游標那根(i)＝出量長紅突破週：
1. 收盤 > 週55MA；週21MA 向上且 > 週55MA。
2. 暖升K：i-20～i-4 週內最早一根紅K，週量 ≥ 該週週13均量×1.3。
3. 暖升後到 i-1 平均週量 ≤ 暖升量×0.7；暖升K之後最低價不破暖升K最低價（停損＝暖升K最低價）。
4. 暖升後波段高 → 3盤最低回測 3~30%。
5. **寶塔3盤＝游標那根收盤 > i-2 高點（連當根共 3 根K）**，不是「3 根K 高低差窄幅」。**有效3盤＝寶塔＋出量（游標週量 > 週5均量）**。使用者說「3盤」一律指這個。
6. 游標前一根收盤對週21MA(SMA) 乖離 −5%~15%。
7. 游標週量 > 前週5均量、收紅、週5均量上升。

**出場（使用者指定）**：週線3盤跌破＝週收盤 < 2根前低點。不要加日線出場或 5% 停損——實測加「虧5%先到」反而更差（勝率 40%→35%、均 +4.8%→+4.1%），週線波動大，5% 常被洗出去。

**回測結果（已跑，2020 起、1951 檔、排除 ETF、5日均量≥5000 張、隨機對照 200 次）**：週3盤跌破出 2117 筆，全部勝率 40%、均 +4.8%、中位 −2.0%；已出場 39%、持有中 16 筆 62%；隨機 34%／+2.6%，選股均報酬 200 次全勝隨機。固定持有 4/10/20 週勝率 51/55/59%。優勢來自少數大賺單、中位數與隨機相同——回報時要講這句，別只報平均。

### 使用者對「主升段」的規格（頸線結構已明確，條件待實作）
- 只要「突破整理區間 → 回測頸線」的波段；純打底（空頭轉折）只出小賺，回測要分成兩組統計，不要併在一起宣稱有效。
- **頸線定義**：往回找兩個低點，頸線＝兩低點中間的那個高點。若為 V 型反轉（找不到兩低點結構），用最後起跌的末跌高當頸線。
- **頸線結構（兩種）**：第一個低點跌破週55MA；弱反彈＝反彈到 55MA 附近就回跌；強反彈＝突破 55MA 才壓回、站上 55 後回測 55MA。
- **穿雲劍**：突破頸線創區間新高那根 K，一定是長紅（實體≥2%）、量 > 週5均量、8/21/55 三線同時向上。
- **回測**：穿雲劍之後回測 55MA 附近（前一根收盤對週21MA 乖離 ≤ 15%）。
- **均量條件**：5/13/34 三條均量同時向上。範例（盟立 2464）MA5 其實向下，實作前要確認嚴格三線向上會不會把標準例濾掉。
- **乖離門檻**：使用者明確指定前一根乖離 ≤ 15%（不是 5%，盟立範例是 +4.4%，15% 已覆蓋）。

標準例（聯發科 2454）：1/19 週、4/13 週命中；10/12 週是量縮凹洞階段，不命中（要提前預警需另加凹洞階段條件）。
