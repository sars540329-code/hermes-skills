# 紅黃綠燈速查表（一頁版）

> ⚠️ 紅黃綠**是警示燈號**：紅 = 危險、黃 = 注意、綠 = 健康。**跟台股漲跌色（紅漲綠跌）無關**。

## 7 個指標閾值

門檻是**下界、上面不封頂** —— 表現特別好不打紅燈，改列在「太漂亮要警覺」那段提醒。

| # | 指標 | 直覺意義 | 🔴 紅燈 | 🟡 黃燈 | 🟢 綠燈 |
|---|------|---------|--------|--------|--------|
| 1 | **CAGR** | 年化報酬 | < 5% | 5 – 10% | ≥ 10% |
| 2 | **Sharpe** | 風險調整後報酬（上下波動都算） | < 0.5 | 0.5 – 1.0 | ≥ 1.0 |
| 3 | **Sortino** | 只懲罰下跌的波動（貼近抱不抱得住） | < 0.8 | 0.8 – 1.5 | ≥ 1.5 |
| 4 | **Calmar** | CAGR ÷ \|MDD\| | < 1 | 1 – 3 | ≥ 3 |
| 5 | **MDD** | 最大回撤 | < -25% | -25% ~ -15% | ≥ -15% |
| 6 | **Profit Factor** | 賺 ÷ 虧 | < 1.2 | 1.2 – 1.5 | ≥ 1.5 |
| 7 | **勝率** | 賺錢的筆數占比 | < 40% | 40% – 50% | ≥ 50% |

> 💡 **MDD 數字越靠近 0 越健康**（-10% 比 -30% 健康）。`MDD < -25%` = 跌得比 -25% 還深。

### ⛔ Sharpe 與 Sortino 同等重要，兩個都要上燈、並列判讀

不是二選一。Sortino 只懲罰下跌波動，貼近「抱不抱得住」的實盤體驗；
Sharpe 上下波動都算，是跟任何人溝通都對得上的通用語言。

兩個燈不一致時要明說差在哪：
「Sharpe 綠 / Sortino 黃 → 整體報酬夠，但下行波動仍偏大」。

**Sortino 的算法只有一種是對的**：

```
downside_dev = sqrt( mean( min(daily_ret, 0)² ) )      ← 分母用「全部期數」
```

⛔ 不可以寫成 `daily_ret[daily_ret < 0].std()` —— 那是「負報酬繞自己平均數」的離散度，
分母 N 的定義跟 Sharpe 不一致，會算出 Sortino < Sharpe 的假訊號。

## 太漂亮要警覺（不打紅燈，但要回頭查）

- **CAGR > 50%** — 太好不真實，通常踩到五大陷阱之一（多半是偷看未來或過度擬合）
- **Sharpe > 3.0** — 機構級也很少超過；超過先懷疑 look-ahead 或存活者偏差
- **Profit Factor > 3** — 檢查是不是少數幾筆大賺撐起來的

## 致命組合（直接淘汰）

- Sharpe > 2.0 **且** 交易筆數 < 30 → 統計不顯著、純運氣
- CAGR > 30% **且** MDD 比 -5% 還淺 → 數學上幾乎不可能、去查 bug
- Sortino ≤ Sharpe → 少見但非不可能。**先查 equity 是不是逐日計價**（見下）

### 最容易做假的一件事：equity 曲線的記帳方式

持倉期間**每天都要用當日收盤價計算未實現損益**（mark-to-market），
出場當天才結算成已實現。

⛔ 如果把整筆損益記在「進場那一天」，出場日完全不動，那條曲線會變成一串階梯：
**MDD 會嚴重低估**、Sharpe／Sortino／最長連虧期全部失真。
`backtester_template.py` 已經修成逐日計價，自己寫的 backtester 要照同樣做法。

## 綜合判讀流程

```
1. CAGR ≥ 10%?
   ├─ No  → 報酬端沒有超額表現。往下看它在風險端有沒有價值
   │        （低報酬但極低回撤的策略，仍可能當作配置的一部分）
   └─ Yes → 繼續

2. Sharpe ≥ 1.0 且 Sortino ≥ 1.5?
   ├─ 兩個都不到 → 報酬不穩定、放棄或大改
   ├─ 只有一個到 → 記下差在哪（Sharpe 高 Sortino 低 = 下跌時特別難熬）
   └─ 都到     → 繼續

3. Calmar ≥ 1.0?
   ├─ No  → MDD 太重、加資金管理層或縮倉
   └─ Yes → 繼續

4. MDD ≥ -15%?（跌幅淺於 15%）
   ├─ No  → 回撤太深、加資金管理層或縮倉
   └─ Yes → 通過初步審核 → 進入「五大陷阱」掃雷
```

## AI vs XQ 對標規則

| 差距 | 燈號 | 行動 |
|------|------|------|
| ≤ 5% | 🟢 一致 | 兩邊算法 ＋ 假設一致 → **可以進下一階段驗證** |
| 5% – 10% | 🟡 接受 | 通常滑價或 ATR 公式不同 → **可接受、要記原因** |
| > 10% | 🔴 警告 | 算法或資料源有重大差異 → **必須找出原因** |

**差 > 5% 常見原因**：
1. ATR 計算法（XQ 用 Wilder's RMA、Python 常用 SMA — 差異可達 30%）
2. 滑價假設不同
3. 資料來源（XQ 內建 vs 雪鴞／yfinance 還原股價）
4. 時間視窗（是否包含進場當根 bar）
