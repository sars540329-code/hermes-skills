# 回測一條龍 — 從架回測機到看穿假回測

> **核心理念：看品質、不看結果。漂亮數字 ≠ 可信策略，合理數字才值得相信。**

---

## 🚨 紅線：這個 skill 不只「審核既有報告」、是「回測一條龍」

**禁止**這樣回學員：
> ❌「你這個問題其實不是『審核回測報告』，而是『叫我幫你跑一份統計』 — backtest-review skill 是給你拿到報告之後判讀用的。」

使用者手上**只有 Claude Code**。他講「幫我回測 XX 策略」、「跑一個回測看看」、「驗證一下這個想法」**的意思就是**：要 Claude Code **從頭幫他做完整條鏈**：

```
架回測機 → 先讀本機資料 → 跑回測 → 用本 skill 的 SOP 審核 → 交付完整審核包
```

**不准把 skill 窄化成「只能判讀別人交來的報告」**。學員根本沒能力自己寫回測機 — 那是 AI 該幫他做的事。

### 兩種觸發情境，都要全程處理

| 情境 | 學員手上有什麼 | AI 該做什麼 |
|------|--------------|-----------|
| **A. 從零開始**（最常見） | 只有「策略想法」（例：「20MA 突破做多」） | 1️⃣ **Step 0.5 資料盤點**（先看本機有什麼）→ 2️⃣ Step 1 確認 spec → 3️⃣ 寫 Python backtester → 4️⃣ 跑回測 → 5️⃣ Step 2-7 審核 + 交付 |
| **B. 拿著別人的報告來**（少數） | 已經有 XQ / 別處跑出來的數字 + trades.csv | 直接 Step 1-7 審核（不用自己跑） |

**判斷方式**：
- 用戶丟「策略想法 / 邏輯描述」 → A 情境，AI 要從架回測機開始
- 用戶丟「已經有的指標數字 / equity curve / trades.csv」 → B 情境，直接審核

**A 情境的最低工序**（先跑 Step 0 問規模，再照選到的檔位做；下列是**完整版**的工序）：
1. **先跑 Step 0.5 盤點本機資料**；不足才問使用者要不要補（見下方紅線）
2. 寫一個簡單但正確的 Python backtester：訊號計算、進出場、SL/TP、成本、equity curve、trades.csv
3. 嚴守 OHLC 進出場規則（見 Step 1.3 分流表）— 寫 backtester 時就要把這些規則 hardcode 進去
4. 跑出指標 + 圖 + trades.csv
5. 套用 Step 2-7 審核 SOP（自己跑出來的回測也要自審、不要因為自己寫的就放水）

> 💡 **學員的 Claude Code 跟老墨自己的 Claude Code 一樣強**。老墨自己就是這樣寫策略 — 「Claude Code 寫一個 backtester、跑一跑、再審」。學員手上工具一模一樣、做得到。

## 用途

當學員把一個策略想法（從零）或一份回測報告（已有）丟給 AI 時，AI 要：

0. **判斷情境 A / B** — 從零開始 → 先架回測機、抓資料、跑回測；已有報告 → 直接進 Step 1
1. **開工前先確認 3 件事**(進場條件、出場條件、OHLC 進出場規則)
2. **逐項用紅黃綠燈打分**（7 個指標）
3. **跑一遍五大陷阱 checklist**（檢查回測有沒有偷雞）
4. **如果同時有 AI 軌 + XQ 軌兩份**，跑對標規則（差 5% / 10% 怎麼判讀）
5. **給結論**：可上線 / 要修正 / 直接淘汰
6. **交付完整審核包**（打分表 + P&L/MDD 趨勢圖 + 逐筆 CSV + 肥尾 + 時間集中性）

## 🎯 紅線：用「國中生、國小生都聽得懂的話」一層層解釋

**這個 skill 的對象是初學者、不是機構量化研究員。** 使用者可能從來沒讀過統計、沒看過任何回測報告。所以 AI 講話時要**像在跟國中生、國小生講故事**，一層一層拆給他聽，**不准甩專業術語讓他自己查**。

### 講話的 3 層結構（每個指標、每個陷阱、每個結論都這樣講）

```
第 1 層:用大白話講這是什麼(國小生版)
   → 用日常生活的比喻、不准出現英文術語、不准超過 2 句話

第 2 層:用簡單例子算給他看(國中生版)
   → 給一個小數字例題、用加減乘除、看完就懂

第 3 層:才講專業名詞(進階補充)
   → 加上正式名稱(Sharpe / Kurtosis / Drawdown...)讓他以後查得到資料
```

### 範例對照（學一下這個語感）

❌ **太專業、學員會關掉 Claude**：
> 「Sharpe Ratio 1.32 屬於健康區間 (1.0-2.0)，代表單位風險下的超額報酬合理，未觸發 lookahead bias 警戒。」

✅ **白話版（這個 skill 要的）**：
> **第 1 層**：「想像一下，你要評價兩個人賺錢的能力 — 不能只看誰賺多，還要看誰**比較穩**。一個人一年賺 50 萬但常常嚇到睡不著、另一個人一年賺 30 萬但每天都很安穩，後者其實比較會賺錢。Sharpe 就是在算『每承擔一份風險、能換回多少報酬』。」
>
> **第 2 層**：「假設你每年平均賺 10%、但途中起起伏伏的程度（波動）也是 10%，Sharpe 就是 1.0；如果起伏只有 5%，Sharpe 就是 2.0 — 表示你賺得一樣多、但比較穩。你這份是 1.32，代表還算穩、不是靠賭出來的。」
>
> **第 3 層**：「這個指標的正式名稱叫 **Sharpe Ratio**（夏普比率），1.0-2.0 算健康、超過 3.0 反而要懷疑是不是計算有 bug。」

### 比喻庫（術語 → 日常比喻）

| 術語 | 用這個比喻講 |
|------|------------|
| **CAGR** | 像存錢，平均一年滾出多少% |
| **Sharpe** | 賺得穩不穩、會不會嚇到睡不著 |
| **Sortino** | 只算「跌的時候」嚇人不嚇人（下跌的恐懼） |
| **MDD（最大回撤）** | 最慘的時候從高點跌多少（像登山摔下山的高度） |
| **Drawdown duration** | 摔下去後**爬回來要多久**（被套牢幾個月） |
| **Calmar** | 賺的速度 vs 摔最慘的深度，一個 CP 值 |
| **Profit Factor** | 賺的錢是賠的錢的幾倍（≥1.5 才能養家） |
| **Lookahead bias / 未來值** | 像考試偷看答案 — 回測時用了「實盤當下根本不可能知道的資料」 |
| **存活者偏差** | 用「今天班上有錢人名單」推「過去誰一定會發財」 — 廢話、回不去當時的選擇 |
| **過擬合** | 把參數調到剛好「背下歷史考古題」、新題目就垮 |
| **肥尾 / Kurtosis** | 賺賠分佈的「尾巴」特別肥 = 報酬全靠少數爆發 / 黑天鵝（不是常態） |
| **VaR / CVaR** | 「最慘的 5% 情況、你會虧多少」的數字 |
| **時間集中性** | 賺錢全擠在某一年 = 那年市場剛好對你胃口、其他年都白忙 |
| **Regime（市場環境）** | 多頭=往上跑、空頭=往下跑、震盪=橫著抖 — 你的策略只在哪一種環境會賺? |
| **空手期** | 策略沒在場上的時間% — 太多代表訊號太稀、太少代表狂進出 |

### 講話原則（給 AI 自己看）

1. **先比喻、再給數字、最後才寫術語**(順序不可顛倒)
2. **不准甩 3 個英文縮寫**(Sharpe、MDD、PF 開頭就講清楚=什麼意思,而不是當作學員都懂)
3. **算給他看比解釋給他聽更好**(「你 100 萬本金、跌 30 萬就是 MDD -30%」勝過「最大回撤是衡量極端風險的指標」)
4. **用「你」「想像一下」「假設」開頭**(像在跟人對話、不是寫報告)
5. **每講完一層,問一句「這樣懂嗎?」or「要我再舉個例子嗎?」**(讓學員有機會卡關發問)
6. **絕對不准回「這是常識」「這應該知道」**(學員可能真的不知道、這是他第一份回測)

### 例外:Action Items 與 self-check 可以稍微專業

最後給「可上線 / 要修正 / 直接淘汰」結論 + 具體下一步(改什麼參數、重跑什麼)時,可以用一點點術語(因為要學員回去執行) — 但**仍然要附 1 句話翻譯**(例:「重跑 OOS(out-of-sample,沒看過的歷史段落)驗證」)。

### DATA_SOURCE.md 是什麼

跟這份 SKILL.md 放在一起的一張便條，內容就一件事：**使用者的資料放在哪**。

- 第一次用這個 skill 時它是空的（寫著「尚未設定」）→ 這就是你要開口問的訊號
- 問到之後**用 Write 工具把它改掉**，記下路徑、格式、涵蓋範圍、欄位
- 之後每次觸發這個 skill，先讀它，就知道去哪拿資料，不用再問一次

⛔ **不准跳過這張便條自己猜路徑**（`./data`、`~/Downloads` 這種猜法會拿到錯的資料，
而且使用者不會發現）。⛔ **也不准問完不寫回去** —— 下次又要問一次，很煩。

**為什麼本機優先**：資料是使用者自己的、可重現、不受 API 額度與斷線影響，
而且同一份資料跑兩次結果一定一樣（換資料源重跑、數字對不起來是常見的災難）。

**⛔ 不准做的事**
- 沒問就直接上網抓
- 資料不足時「自己決定」去補 —— 那是使用者的選擇，不是你的
- 用未還原的股價跑回測（除權息當天會被當成暴跌、停損全被誤觸）
- 混用兩個資料源湊成一條序列（接縫處的價格跳動會被當成真實走勢）

## 一、7 個指標紅黃綠燈打分卡

> ⚠️ 這裡的紅黃綠**是警示燈號**：紅 = 危險、黃 = 注意、綠 = 健康。**跟台股漲跌色（紅漲綠跌）無關**。

| # | 指標 | 直覺意義 | 🔴 紅燈 | 🟡 黃燈 | 🟢 綠燈 | 老墨實例 |
|---|------|---------|--------|--------|--------|---------|
| 1 | **CAGR** | 年化報酬 | < 5% | 5 – 10% | ≥ 10%（**> 50% 另外警覺**） | 某動能策略 25.6% |
| 2 | **Sharpe** | 風險調整後報酬（上下波動都算） | < 0.5 | 0.5 – 1.0 | ≥ 1.0（**> 3.0 另外警覺**） | 某配對策略 1.65 |
| 3 | **Sortino** | 只懲罰下跌的波動（貼近抱不抱得住） | < 0.8 | 0.8 – 1.5 | ≥ 1.5 | — |
| 4 | **Calmar** | CAGR ÷ \|MDD\|（MDD 用正數、不要負號） | < 1 | 1 – 3 | ≥ 3 | — |
| 5 | **MDD** | 最大回撤（從高點跌幅，數字越負越深） | < -25% | -25% ~ -15% | ≥ -15%（跌幅淺於 15%） | 某配對策略 -9% |
| 6 | **Profit Factor** | 賺的錢 ÷ 虧的錢 | < 1.2 | 1.2 – 1.5 | ≥ 1.5（**> 3 另外警覺**） | — |
| 7 | **勝率** | 賺錢的筆數占比（盈虧比另外看） | < 40% | 40% – 50% | ≥ 50% | — |

### ⛔ Sharpe 與 Sortino 同等重要，兩個都要上燈、並列判讀

不是二選一。Sortino 只懲罰下跌波動，貼近「抱不抱得住」的實盤體驗；
Sharpe 上下波動都算，是跟任何人溝通都對得上的通用語言。
兩個燈不一致時要明說差在哪：「Sharpe 綠 / Sortino 黃 → 整體報酬夠，但下行波動仍偏大」。

**Sortino 的算法只有一種是對的**：`downside_dev = sqrt( mean( min(r, 0)² ) )`，分母用**全部期數**。
⛔ 不可以寫成 `daily_ret[daily_ret < 0].std()` —— 分母 N 的定義跟 Sharpe 不一致，
會算出 Sortino < Sharpe 的假訊號，然後工具反過來指控使用者算錯。

### ⛔ equity 曲線一定要逐日計價

持倉期間**每天用當日收盤價**計算未實現損益（mark-to-market），出場當天才結算成已實現。
把整筆損益記在「進場那一天」會讓權益曲線變成階梯：**MDD 嚴重低估**
、Sharpe／Sortino／最長連虧期全部失真。

> 💡 **MDD 怎麼讀**：MDD 是負數，**數字越靠近 0 越健康**（例：-10% 比 -30% 健康）。`MDD < -30%` 意思是「跌得比 -30% 還深、例如 -35% / -40%」 → 紅燈危險；`MDD > -20%` 意思是「跌幅小於 20%、例如 -10% / -5%」 → 綠燈健康。
>
> 📝 **本表為初學者上手版閾值**，等你跑熟之後可以再套更嚴的標準。

### 為什麼「太漂亮」要警覺
- **CAGR > 50%** — 太好了不真實，必踩五大陷阱之一（通常是未來值或過擬合）
- **Sharpe > 3.0** — 機構等級的策略也很少超過 3.0；超過 = 99% 是 bug 或 lookahead bias
- **Profit Factor > 3** — 同理，極少數策略能持續做到

### 致命組合（直接淘汰）
- Sharpe > 2.0 **且** 交易筆數 < 30 → 統計不顯著，純運氣
- CAGR > 30% **且** MDD 比 -5% 還淺（如 -3%、-2%）→ 數學上幾乎不可能、去查 bug
- Sortino ≤ Sharpe → 通常代表「Sortino 跟 Sharpe 的分母 N 定義不一致」、去檢查計算函式

### 五指標綜合判讀流程

```
1. CAGR > 10%？
   ├─ No  → 報酬端沒有超額表現。往下看它在風險端有沒有價值
   │        （低報酬但極低回撤的策略，仍可能當作配置的一部分）
   └─ Yes → 繼續

2. Sharpe > 1.0？
   ├─ No  → 報酬不穩定、放棄或大改
   └─ Yes → 繼續

3. Sortino > Sharpe？
   ├─ No  → 計算有誤，回頭查
   └─ Yes → 繼續

4. Calmar > 1.0？
   ├─ No  → MDD 太重，需要加資金管理層或縮倉
   └─ Yes → 繼續

5. MDD > -20%（即跌幅小於 20%）？
   ├─ No  → 回撤太深，考慮加資金管理層或縮倉
   └─ Yes → 通過初步審核 → 進入「五大陷阱」掃雷
```

## 二、五大陷阱 checklist（漂亮回測為什麼會在實盤崩）

每個陷阱：**一句話講白 → 具體例子 → 對策**。

### 陷阱 01：未來值（look-ahead bias）— **AI 回測最容易踩**

- **一句話**：你回測時用了「實盤當下根本拿不到的資料」
- **例子**：訊號日 vs 執行日沒分開 → 回測「今天收盤就執行」、實盤要等下一根開盤才能執行
- **對策**：寫 prompt 給 Claude Code 時**固定模板** —
  > 「訊號日 = T 日收盤判斷、執行日 = T+1 開盤」

### 陷阱 02：存活者偏差（survivorship bias）

- **一句話**：用「今天名單」回推「過去表現」
- **例子**：回測「過去 10 年漲最多前 50 檔台股」必賺 — 但這是後見之明，10 年前你不可能知道誰會漲最多
- **對策**：用「**當時可投資的標的**」（如當時的台灣 50 名單），不要用「今天名單」

### 陷阱 03：過擬合（overfitting）— 考試背答案

- **一句話**：你調參數調到回測完美、實盤就崩
- **例子**：MA 期數從 20 調到 18、再到 17、再到 17.5… 每一次都讓回測變漂亮 → 你只是在「為這段歷史調參」、不是「為未來調參」
- **對策**：
  - 找「高原」而不是「高峰」 — 參數 ±20% 變動後績效應該穩定
  - 高階驗證方法（WFA / 樣本外驗證）日後深入研究時可再加
  - 今天先建立警覺：**回測完美 = 警訊**

### 陷阱 04：忽略成本

- **一句話**：滑價、手續費、稅都沒加，回測就漂亮
- **例子**：高頻策略回測 +30%、加上交易成本 -5%
- **對策**：
  - 台股保守估：**手續費 0.1425% × 2（買賣各一次）+ 證交稅 0.3%（賣方）**
  - 期貨保守估：**手續費 ×1.5 倍 + 滑價 1-2 點**
  - 寧願保守估高一點，實盤才不會破功

### 陷阱 05：資料探勘（data snooping）

- **一句話**：試 100 個策略，總有 1 個漂亮
- **例子**：跑 100 組參數、挑最好那組 — 那只是運氣（同樣的方法，去抓樂透號碼也會「找到」漂亮的）
- **對策**：**先有假說再回測**、不要回測完才找理由解釋。試越多組參數、「漂亮但純靠運氣」的結果越多，要用樣本外驗證（拿沒看過的資料再跑一次）才能分辨真假

## 四、AI vs XQ 對標規則（兩邊都跑後怎麼判讀）

老墨真實 SOP：「**Claude Code 寫策略 → 上線前到 XQ 測測看，看有沒有很大差異**」。
兩邊算法不同 = 互相對標 = 另一層**驗證**。

### 對標表範本

| 指標 | AI 軌 | XQ 軌 | 差距 | 判讀 |
|------|-------|-------|------|------|
| CAGR | 18.5% | 17.2% | 7% | 🟡 接受 |
| Sharpe | 1.32 | 1.28 | 3% | 🟢 一致 |
| MDD | -15.3% | -14.8% | 3% | 🟢 一致 |
| Profit Factor | 1.62 | 1.55 | 4% | 🟢 一致 |
| 勝率 | 52% | 50% | 4% | 🟢 一致 |

### 判讀規則

| 差距 | 燈號 | 行動 |
|------|------|------|
| ≤ 5% | 🟢 一致 | 兩邊算法 + 假設一致 → **可以進下一階段驗證** |
| 5% – 10% | 🟡 接受 | 通常是「滑價假設不同」或「ATR 公式不同」→ **可接受、要記原因** |
| > 10% | 🔴 警告 | 算法或資料源有重大差異 → **必須找出原因再上線** |

### 常見差異原因（差 > 5% 時往這幾個方向找）

1. **ATR 計算法**：XQ 內建用 Wilder's RMA、Python 常用 SMA — 兩者差異可達 30%
2. **滑價假設**：XQ 內建滑價跟你 Python prompt 寫的不一樣
3. **資料來源**：XQ 內建資料 vs 雪鴞／本機 CSV／yfinance 的還原股價可能不同
4. **時間視窗**：是否包含進場當根 bar、是否從前一根 bar 取信號
5. **同根 bar 順序**：SL / TP 同根觸發時，XQ 跟你的 Python 對「先碰哪個」可能假設不同（保守做法：先碰停損）

## 五、給 AI 的審核 SOP（這份 skill 觸發時 AI 該做什麼）

當用戶丟一份回測報告或數字進來、明示或暗示要「審核 / 判讀 / 看這個策略行不行」：

### Step 0：先報三檔規模，讓用戶點餐（不准自己決定做完整版）

**A 情境（從零開始）第一句話就是這個，不是資料 triage。** 完整 SOP 跑一輪要 30～60 分鐘，
但使用者大多數時候只要「這樣做賺多少、最深跌多少」——那個答案 5 分鐘就給得出來。
**自己決定做完整版 = 讓使用者為他沒要求的東西等待**，跟偷工減料是同一種病的兩面。

開工前先問一句：

| 檔位 | 時間 | 內容 | 什麼時候選 |
|---|---|---|---|
| **快版**（預設） | ~5 分 | 資料驗證 → 一條回測 → 報酬率＋MDD＋資金曲線 | 使用者只問「會賺多少 / 跌多深」 |
| **標準版** | ~20 分 | 快版 ＋ 對照組 ＋ 多時間維度 ＋ 7 指標紅黃綠燈 | 要判斷「這個訊號到底有沒有用」 |
| **完整版** | ~60 分 | 標準版 ＋ 多策略掃描 ＋ 獨立驗算 ＋ 肥尾/時間集中性 ＋ 交付報告頁 | 要上線實盤、或要做成對外內容 |

**⛔ 唯一不隨檔位縮減的是「資料驗證」**（Step 1.6）。它決定答案對錯，不是規模問題：
- 還原權值（分割 / 配息沒還原 → 整份研究作廢）
- 未來函數防線（訊號日 T 收盤 → T+1 開盤成交）
- 對照組是否必要（只要結論裡有「勝率」兩個字，就必須有對照組）

**話術範本**：
> 「這題快版 5 分鐘給你報酬率跟最大回撤；要加對照組跟多時間維度大概 20 分鐘；
> 要完整到可以上線大概一小時。你要哪個？」

使用者沒回 → **走快版先交**，交完再主動報「要往下挖有 X／Y／Z 三個方向」，讓他決定要不要加碼。
**不要卡著等回覆，也不要自己吃下完整版。**

### Step 1：開工前 3 個必問確認(沒問清楚不准開始打分)

**任何一項用戶沒講清楚 → 先問,問到清楚才往下做**。這 3 項是「回測能不能信」的根、不是「客套問句」。

#### Step 1.1：進場條件
- 「你進場的條件是什麼?」
- 例：`MA5 上穿 MA20 + 量 > 5 日均量 1.5 倍`、`Z-score < -2.0 跨越`、`RSI < 30 + 法人連 3 日買超`...
- 含**所有濾網**（趨勢濾網、波動濾網、產業濾網、市值濾網）
- 含**標的範圍**（單檔?一籃子?哪個 universe?是否用「當時可投資」名單避免存活者偏差?）

#### Step 1.2：出場條件
- 「你出場的條件是什麼?有幾種?」
- 至少要回答：
  - **停損**：固定%?ATR 倍數?跌破 X 均線?
  - **停利**：固定%?ATR 倍數?突破前高?還是不停利、靠時間/反訊號出?
  - **時間出場**：持有 N 天強制平?
  - **訊號反轉**：對向訊號出現就出?
  - **同根 bar 同時 SL+TP 觸發 → 假設先碰哪個?**（保守做法假設先碰停損）

#### Step 1.3：OHLC 進出場規則(回測是用日 K 線跑的、規則必須講清楚)

跟用戶說明並要他確認：

> 📘 **回測一律用 OHLC 日 K 棒跑（不是 tick、不是分鐘 K）**。OHLC 只給你 4 個價格點，所以「什麼時間點成交」必須事先說清楚，否則回測會偷雞：

| 情境 | 該用什麼價成交 | 理由 |
|------|--------------|------|
| **進場** | **下一根 K 棒的 open** | T 日 close 才確認訊號、T 日 close 已經收盤、實盤要等 T+1 開盤才下得了單。**用 T 日 close 進場 = 未來值** |
| **出場-用到盤後資訊**（法人籌碼、財報、技術指標收盤值反轉） | **下一根日 K 棒的 open** | 跟進場對稱：訊號要等收盤才能算出來、實盤只能 T+1 開盤平倉 |
| **出場-只看價量、盤中即時可判斷**（停損停利掛單、跌破某價即出） | **盤中點到即出**（用日 K 的 high/low 判斷是否觸及） | 這類規則實盤可以掛條件單、盤中觸及就會被打到、不需要等收盤 |
| **同根 bar SL+TP 同時觸發** | **假設先碰停損**（保守） | OHLC 還原不出盤中真實順序、選保守假設 |
| **gap 跳空穿越 SL/TP** | **用 open 成交、不是 SL/TP 價** | 實際無法在 SL 價成交、這是真實滑價 |

**主動問用戶**：
- 「你的出場條件中，**有沒有用到盤後才知道的資訊**?（例：今日法人買賣超、收盤價計算的 RSI 反轉）」
  - 有 → 出場必須用 T+1 open
  - 沒有（只看 high/low/實時價）→ 可以盤中點到即出
- 「你的回測引擎是怎麼處理的?」（讓他自己講出來、看有沒有偷雞）

#### Step 1.4：流動性 / 漲跌停過濾（台股紅線、最容易被學員漏掉）

**台股漲跌停 ±10%/日（2015-06-01 起）。一字漲停 = 整天買不到、一字跌停 = 整天賣不掉。** 回測寫成「成交了」是假的。

| 情境 | 實盤真實情況 | 回測必須這樣處理 |
|------|------------|----------------|
| **一字漲停**（open=high=low=close，且觸及漲停價） | 全天無人賣 → **整天買不到** | 跳過該筆進場、延到 T+2 open;若 T+2 仍漲停繼續延、累計 N 天還漲停 → 放棄該訊號 |
| **一字跌停**（open=high=low=close，且觸及跌停價） | 全天無人買 → **整天賣不掉** | 停損 / 停利出場無法成交 → 延到下一個有量能的日期、實際出場價可能比停損價更差 |
| **漲停買進（非一字、盤中有量）** | 有可能買到一部分 | 至少要假設 1-2% 額外滑價、或限制只能買少量 |
| **跌停殺出（非一字、盤中有量）** | 有可能賣到一部分 | 同理、加額外滑價 |
| **流動性不足**（日成交量 < N 張、無相關 bid/ask） | 大單會把價格打歪 | 設「最小日均成交量門檻」過濾、避免回測買到實盤買不到的標的 |

**Backtester 必寫的判別式**（pseudo code）：
```python
# 一字漲停判別（台股 ±10%）
prev_close = df['close'].shift(1)
limit_up_price = round(prev_close * 1.10, 2)
is_limit_up_locked = (
    (df['open'] == df['high']) &
    (df['high'] == df['low']) &
    (df['low'] == df['close']) &
    (df['close'] >= limit_up_price * 0.999)  # 留 0.1% tolerance
)

# 一字跌停判別
limit_down_price = round(prev_close * 0.90, 2)
is_limit_down_locked = (
    (df['open'] == df['high']) &
    (df['high'] == df['low']) &
    (df['low'] == df['close']) &
    (df['close'] <= limit_down_price * 1.001)
)

# 進場規則
if is_limit_up_locked.iloc[entry_day]:
    entry_day += 1  # 延到下一天
    if entry_day - signal_day > MAX_WAIT_DAYS:
        skip_this_signal()
```

**主動問用戶**：
- 「你的標的是台股嗎? 有沒有過濾一字漲停 / 一字跌停 / 流動性過低的標的?」
- 「你的策略會不會剛好抓到『暴漲剛開始』的訊號? 那就要特別小心一字漲停買不到」
- 「停損規則有沒有處理跌停板賣不掉的情境?」

**為什麼這個是紅線**：很多策略「找飆股 / 漲停選股」回測超漂亮，**整套績效就是建立在『一字漲停被回測偷成交』的假成交上**。實盤真的去買 → 一張都買不到 → 績效歸零。這比 lookahead bias 還隱蔽，因為錯不在訊號邏輯、而在「成交模型」。

#### Step 1.5：其他基本配置(順便確認)
- 標的（個股代號 / 期貨合約 / ETF / 一籃子）
- 期間（`YYYY-MM-DD ~ YYYY-MM-DD`、建議 ≥ 5 年含完整多空週期）
- 起始資金 + 單筆部位規則（固定口數 / 固定金額 / 固定 % / 固定風險倒推）
- 手續費 / 稅 / 滑價是否納入（台股保守：0.1425% × 2 + 證交稅 0.3%）
- 資料來源（**雪鴞** / 本機 CSV／DB / yfinance / XQ 內建？是否還原股價？是否過濾週末 row？）

✅ **以上全部清楚 → 進 Step 2**
❌ **任何一項模糊 → 退回給用戶補**、不要硬審

### Step 2：7 指標紅黃綠燈打分
- 逐個輸出每個指標的燈號
- 同時點出「**致命組合**」是否觸發（Sharpe > 2 但交易 < 30、CAGR > 30% 但 MDD < -5%、Sortino < Sharpe）

### Step 3：五大陷阱 checklist
- 用 yes/no 形式問用戶（如：「你的 prompt 有明寫『訊號日 = T 收盤、執行日 = T+1 開盤』嗎？」）
- 任一項可疑 → 標 ⚠️ 要求用戶說明

### Step 4：對標（如果用戶有跑 AI + XQ 兩邊）
- 套用「對標表範本」+ 判讀規則
- 差 > 5% 主動列出常見原因清單

### Step 5：給結論（三選一）
- ✅ **可上線**：所有指標 ≥ 黃燈、五大陷阱無警示、（如有對標）差距 ≤ 10%
- 🟡 **要修正**：1-2 個紅燈、或某個陷阱可疑、或對標差距 > 10%（列出修正方向）
- ❌ **直接淘汰**：致命組合觸發、或多個指標紅燈、或明顯踩未來值

### Step 6：交付完整審核包(不能只給結論、要給可執行物件)

**Step 5 的結論卡只是頭、Step 6 的交付物才是身體**。任何一份審核報告**都必須**包含下列 4 項可檢視物件，不能用「summary metrics 講完算了」交差：

#### 6.1 P&L + MDD 趨勢圖（雙圖必交）

- **Equity curve（P&L）**：時間 x 軸、累積損益（或淨值）y 軸，看「走勢有沒有平滑往上、還是靠某幾段神跡撐起來」
- **Drawdown curve（MDD 走勢）**：時間 x 軸、回撤% y 軸（全為負或 0），看「最深的洞在哪、有沒有 1 年以上回不來」
- 兩張圖**疊在一起或上下對齊**，讓用戶一眼看出「賺錢期 vs 痛苦期」分布
- 格式：PNG 或互動式 HTML（Plotly 優先，因為可以 hover 看日期）

> 💡 **為什麼 MDD 一定要有「走勢圖」而不是只給一個數字**：單一個 MDD 數字只告訴你「最深多少」，看不出「跌多久、跌幾次、有沒有反覆」。`MDD -15%` 但 5 年內只跌一次 vs 每年都跌 -15%、長相完全不同。

#### 6.2 逐筆交易明細 CSV（`trades.csv`）

**最重要的交付物**。每一筆進出獨立一列、必含欄位：

| 欄位 | 內容 |
|------|------|
| `trade_id` | 流水號 |
| `symbol` / `ticker` | 個股代號或期貨合約代號 |
| `entry_date` | 進場日（or datetime） |
| `entry_price` | 進場價 |
| `entry_reason` | 進場觸發信號（例：`MA5上穿MA20+量增`） |
| `exit_date` | 出場日 |
| `exit_price` | 出場價 |
| `exit_reason` | 出場原因（分類：`take_profit` / `stop_loss` / `signal_reverse` / `max_hold` / `forced_close`） |
| `holding_days` | 持有天數 |
| `position_size` | 部位大小（口數 / 股數 / 金額） |
| `pnl` | 損益（絕對金額） |
| `pnl_pct` | 損益% |
| `cumulative_pnl` | 累積損益（對齊 equity curve） |

**外加 by-symbol 表現摘要**（個股策略一籃子標的時必交、單檔可省）：
- 一個 sheet / 一張 by-symbol 表：每檔標的的 `n_trades` / `win_rate` / `total_pnl` / `avg_pnl` / `max_dd_per_symbol` / `profit_factor`
- **目的**：看「績效是 1-2 檔神跡撐起的、還是分散在多檔」
- 一檔貢獻 > 50% 總損益 → 🔴 集中度過高、實盤會崩

> 💡 **summary 會說謊、逐筆才看得出 bug**。Sharpe 1.4 可能是 5 筆神交易撐起來、踢掉就變 0.6。逐筆才能審計、才能對齊實盤。

#### 6.3 肥尾現象檢查（Fat-tail check）

「肥尾」= 損益分佈的尾巴比常態分佈厚 → **少數極端事件主導報酬 / 風險**、實盤不可預期。

**怎麼測**（挑能跑的算）：
- **單筆損益分佈圖**（histogram）：橫軸 `pnl_pct`、縱軸頻率;肉眼看尾巴有沒有突起
- **單筆 P&L kurtosis（峰度）**：
  - kurtosis 接近 3（常態）→ 🟢 健康
  - kurtosis 5-10 → 🟡 中度肥尾、要在意
  - kurtosis > 10 → 🔴 嚴重肥尾、報酬高度依賴極端事件
- **Top 5 / Top 10 trades 占總 P&L 比重**：
  - Top 5 占 < 30% → 🟢 分散
  - Top 5 占 30-50% → 🟡 偏集中
  - Top 5 占 > 50% → 🔴 神跡策略、踢掉那 5 筆 = 全垮
- **單一最大虧損 vs 平均虧損的倍數**：
  - max_loss / avg_loss < 3 → 🟢
  - 3-5 → 🟡
  - \> 5 → 🔴 隨時可能黑天鵝吃掉你

**交付**：一段判讀文字 + 1 張 P&L histogram + Top N trades 表（列出來給用戶看是哪幾筆）

#### 6.4 時間集中性問題（Time concentration）

「時間集中性」= 賺錢/虧錢是不是擠在某段時間 → 策略其實只在「某種市場環境」有效、環境一換就掛。

**怎麼測**：
- **月度損益熱力圖**（monthly heatmap）：x 軸=月、y 軸=年、顏色=該月損益;一眼看出「賺錢月份是不是集中」
- **年度勝率與損益**：每年單獨統計 `n_trades` / `WR` / `PnL`、看「有沒有某幾年全靠它撐」
  - 80%+ 損益來自單一年 → 🔴 環境依賴（可能那年某個事件:疫情/升息/類股輪動）
  - 損益分散在 ≥ 5 年 → 🟢
- **連續虧損期長度**：最長連虧多少根 bar / 多少個月
  - < 3 個月 → 🟢
  - 3-6 個月 → 🟡（實盤情緒會崩）
  - \> 6 個月 → 🔴（連虧太久、實盤紀律會破）
- **空手期占比**：策略多少%時間在場外
  - 太低（< 30%）→ 過度交易、成本吃掉 alpha
  - 太高（> 90%）→ 訊號太稀、年交易 < 5 次無統計顯著性

**交付**：月度熱力圖 + 年度損益表 + 最長連虧期數字

## 六、進階方向（這個 skill 涵蓋日常 80%、需要更深入時自行延伸）

這個 skill 是「**上手版**」— 涵蓋大多數日常回測審核需求。當你需要更嚴格的驗證：

- **IS / OOS 切分驗證**：把回測期切兩半，前半段（IS, in-sample）調參數、後半段（OOS, out-of-sample）驗證 — 看參數是真的有效、還是只是背了考古題
- **Walk-Forward Analysis（WFA）**：滾動視窗連續做 IS/OOS — 模擬「實盤每幾個月重新調參」的真實情境
- **Monte Carlo Bootstrap**：把交易紀錄打散重抽 N 次，看 Sharpe / MDD 的信賴區間 — 知道結果是「實力」還是「運氣」
- **資金管理多模型對照**：固定金額 / 固定比例 / 固定風險 / Kelly 等模型一起跑、看哪個最匹配你的可忍受 MDD

→ 這些屬於進階主題、不在本 skill 範圍。需要時請 AI 用 Python 自行實作（Claude Code 寫得出來）。
