# 因子驗證一條龍 — 把「我覺得」變成「我知道」

> **核心理念：一個想法值不值得做成策略，先分開驗證，
> 不要一次疊四個條件然後說它有效。**

---

## 🚨 紅線 1：講結果一律用國小生聽得懂的比喻，而且要直接給建議

**這是本 skill 最重要的一條。** 使用者不是統計系的，
你丟一張「IC 0.031、ICIR 0.4、單調性 0.62」的表格給他，等於什麼都沒交付。

### 每個數字都要三件事一起講

```
 ① 數字        ② 這是什麼（國小生比喻）        ③ 所以你該怎麼做
 IC 0.031  →  「你猜班上名次，猜得有點準」  →  「樣本再拉長，現在還分不清是真準還是運氣」
     └────────── 缺任何一個都算沒講完 ──────────┘
```

- ❌ 「IC 均值 0.031，ICIR 0.41，未達 0.5 門檻」
- ✅ 「這個因子**有點準，但還不夠確定**。就像你猜班上誰考前十名，猜對了幾次 ——
   有可能你真的會看人，也有可能只是運氣好。目前的資料還分不出是哪一種。
   **建議：把期間拉長到 5 年以上，或多放一些股票進來再跑一次。**」

### ⛔ 不准只丟表格就走

**每一個黃燈與紅燈，都要配一句白話說明 ＋ 至少一個具體可執行的調整建議。**
綠燈可以只講一句「這格沒問題」。

### 比喻對照表（照這個講，不要自己另外發明）

| 指標 | 國小生比喻 |
|---|---|
| **多空價差** | 「班上**前 10 名**的平均成績，比**後 10 名**高幾分」。差很多 → 這個排序方式有意義 |
| **Sharpe** | 「開車去學校，一樣的時間到，但一台很穩、一台一路急煞」。Sharpe 高的是穩的那台 |
| **Sortino** | 「只算急煞、不算加速」。你不會因為車子加速快而害怕，你怕的是急煞 —— 這個數字只算讓你害怕的那部分 |
| **IC** | 「你猜班上誰考前十名，猜得準不準」。0 ＝ 完全瞎猜，1 ＝ 全部猜對 |
| **ICIR** | 「平均 50 分的人，是**每次都 50**、還是一次 100 一次 0？」ICIR ＝ IC 的平均 ÷ IC 的起伏。IC 高但 ICIR 低 ＝ 時好時壞，實盤抱不住 |
| **分組階梯（單調性）★ 最重要** | 「排隊有沒有按身高」。把股票按分數切五組，第一組最高、第二組次高…**階梯式一路往下走**才算數；如果**第三組突然最高**，那就不是身高在排隊，是別的東西混進來了。老墨叫它 **IQR** |
| **勝率** | 「10 個月裡面有幾個月是賺的」 |
| **最長連虧** | 「最久連續幾個月都沒賺到錢」＝ **你要忍多久** |
| **樣本期數** | 「你只丟三次骰子，就說這顆骰子有問題？」 |
| **前 5 筆占比** | 「全班總分，是不是靠**一個資優生**撐起來的」。是的話，他一轉學班平均就垮了 |
| **蒙地卡羅** | 「同一副牌，重新洗 5,000 次再打一遍，看有幾次會贏」。這在測「上次贏是不是剛好牌順」 |
| **存活者偏差** | 「只統計還在班上的人的成績」—— 轉學走的（下市的）不算，平均當然好看 |
| **未來值** | 「先偷看答案再作答」。考 100 分不是因為你會，是因為你看到答案了 |
| **過擬合** | 「這把鑰匙只能開這一扇門」。參數改一點點就失效，代表它記住的是這段歷史，不是規律 |

### 紅燈／黃燈 → 直接給這些建議（照抄，不要只說「建議優化」）

| 哪一格不好 | 白話 | 建議這樣調（按順序試） |
|---|---|---|
| **多空價差** < 3% | 前 10 名跟後 10 名差不多 | ① 五組改十組，看最極端的有沒有差<br>② 加流動性門檻，把成交量太小的股票濾掉（它們的報酬雜訊很大）<br>③ 換持有期（一個月改一季）<br>④ 都試過還是平的 → **這個想法可能真的沒用，換一個** |
| **Sharpe** < 0.5 | 有賺，但路上晃太兇 | ① 拉長持有期，減少換股次數<br>② 分組數改少（五組改三組），每組檔數變多、比較穩<br>③ 加一個波動度濾網（把最會晃的股票排除） |
| **Sortino** < 0.8（但 Sharpe 還可以） | 賺是有賺，但跌的時候特別痛 | ① 看逐年表，找出最慘那年市場發生什麼事<br>② 加「大盤跌到季線以下就不做」的條件再驗一次 |
| **IC** < 0.02 | 你猜的名次跟實際結果沒關係 | ① **先檢查分數方向有沒有寫反**（取負號再跑一次，這是最常見的錯）<br>② 看分數的分布，如果九成集中在同一個值，這個因子根本區分不出東西 |
| **ICIR** < 0.3 | 猜得準的月份跟猜錯的月份差很多，時好時壞 | ① 看逐期 IC 走勢，找出失效那幾段市場在幹嘛<br>② 加市場狀態濾網（例：大盤在季線上才用）再驗一次<br>③ 分數改用排名或拉長持有期，減少極端值甩動<br>④ 樣本太少也會不穩 → 期間拉長、股票加多 |
| **分組階梯（單調性）** < 0.5 | 排隊沒有按身高、階梯不成立 | ⛔ **這是最重要的一顆燈，紅燈就不能信**，通常是幾檔極端值在撐<br>① 把分數最極端的 1% 砍掉再跑（winsorize）<br>② 砍掉就沒了 → 本來就是雜訊，丟掉 |
| **勝率** < 50% | 賺的月份比賠的少 | ① 配「風報比」一起看 —— 勝率低但平均賺是平均賠的 2 倍以上，也可以<br>② 兩個都低 → 丟掉 |
| **最長連虧** > 12 個月 | 你要忍一年多都沒賺 | ① 數字再漂亮也不要當主策略，**實盤忍不住**<br>② 找一個「跟它不同時間賺錢」的因子搭配著用 |
| **前 5 筆** > 50% | 靠幾筆神跡撐起來 | ① 把那幾筆拿掉再看剩下的<br>② 拿掉就垮 → 那是運氣不是規律 |
| **樣本** < 36 期 | 骰子丟太少次 | 先補資料，**不要下結論**。老實跟使用者說「樣本不足，這是參考值」 |
| **多數綠燈** | 這個想法站得住 | 下一步用 `backtest-review` 做成完整策略（加進出場、停損、成本）再驗一次。<br>**因子有 alpha ≠ 策略會賺錢** |

## 🚨 紅線 2：這是「一條龍」，不是「幫你判讀別人的表」

**禁止**這樣回使用者：

> ❌「你這個要先有因子分數的資料表我才能幫你看。」

使用者手上**只有 Claude Code 跟一份日線資料**。他說「幫我驗證『站上季線』有沒有用」，
意思就是要你**從頭做完整條鏈**：

```
問清楚想法 → 盤點本機資料 → 把想法寫成分數 → 分組跑報酬
→ 算 IC 與單調性 → 打燈 → 發牌統計 → 蒙地卡羅 → 交付報告
```

**不准把 skill 窄化成「只能判讀既有結果」。** 使用者不會自己寫因子回測 —— 那是 AI 該做的事。

## 這個 skill 在哪一格

三個 skill 是一條線，不重疊。**用錯了會繞遠路：**

| 你手上有的 | 該用哪個 | 它回答什麼 |
|---|---|---|
| 一檔股票代號 | `tv-chart` | 這檔長什麼樣子？ |
| **一個想法** | **`factor-check`（本 skill）** | **這個想法有沒有 alpha？** |
| 一份跑完的回測 | `backtest-review` | 這個策略能不能上線？ |

**先驗因子、再做策略。** 順序反過來 = 你花三天做一個沒有 alpha 的東西。

## ⛔ 三條技術紅線（每次都要遵守，不能因為趕時間跳過）

### 技術紅線 A：一次只驗一個因子

**沒驗證過的因子加在一起 ＝ 噪音 ＋ 噪音。**

- ❌「營收成長 ＋ 站上季線 ＋ 外資買超，一起跑，結果不錯」
- ✅ 三個各跑一次，把不合格的丟掉，剩下的才談組合

不合格的因子**直接丟**，不要想「跟別的組合起來也許會好」。

比喻：三種藥一起吃，病好了 —— 你不知道是哪一種有效，也不知道有沒有一種其實在害你。

### 技術紅線 B：訊號用收盤算、進場用隔天開盤

**任何「定期換股」的驗證都是：第 K 天收盤算分數 → 第 K+1 天開盤進場。**

| 做法 | 對不對 |
|---|---|
| 分數用 T 日收盤算、又用 T 日收盤價成交 | ❌ 偷看答案 —— 你要等收盤才知道分數，不可能用那個收盤價成交 |
| 分數用 T 日收盤算、T+1 日開盤價成交 | ✅ 實盤就是這樣 |
| 報酬算 `close[下期] / close[本期] - 1` | ❌ 對齊上面那個錯的假設 |
| 報酬算 `open[T+1] → open[下期 T+1]` | ✅ 進出場對稱 |

這一天的落差通常吃掉一點報酬，**但不做就是偷雞、實盤會對不上**。

### 技術紅線 C：同分必須同組，而且不准硬編組號

這兩個是同一個坑的正反面，**兩個都要做**：

```
 分數有大量同分（例：42 檔都是滿分 1.0）
        │
        ├─ 用 rank(method="first") 切組
        │      ▼ 同分被「資料順序」硬拆 ＝ 通常是股票代號序
        │      ▼ 頂組系統性偏向代號小的公司（台股＝傳產老公司）
        │      ✗ 這是有方向性的偏誤，不是隨機誤差
        │
        └─ 用 rank(method="average") 或直接 qcut 值
               ▼ 同分共用平均名次 → 必落同一組
               ✓ 正確（學術標準做法）

 同分太多 → qcut 的分位邊界重合 → 當期崩成 3 組（不是 5 組）
        │
        ├─ 寫 grp[1] - grp[5]
        │      ▼ 第 5 組不存在 → 整期默默變 NaN → 下游 fillna(0) → 假的 0
        │      ✗ 不會報錯，你完全不會發現
        │
        └─ 逐期取「標籤最小 − 標籤最大」
               ✓ 不管當期切出幾組都取得到兩端
```

比喻：分組像排隊按身高分五排。**同樣高的人一定要排同一排**（不能因為誰先到就插到前面那排）；
而且如果全班剛好只排出三排，你不能還在喊「第五排出來」—— 那一排沒人，你會以為那天全班都沒來。

**改完分組方法一定要看：報酬表的 NaN 期數有沒有暴增。**

**紅旗症狀**：某個因子的 12 個月報酬「剛好等於 0.0000」→ 幾乎必定是 NaN 被填成 0 的指紋，
回去查有沒有整期被丟掉。

`scripts/factor_test.py` 兩件都已經做好了，直接用就不會踩。

## 五步流程

### Step 0：先問規模，不要自己決定做多大

一句話問使用者，然後照他選的做：

> 「這個因子你要驗到多細？
> **快版（5 分）**：分五組看報酬、單調不單調、打燈。
> **標準版（15 分）**：加 IC、逐年表、多空曲線、互動報表。
> **完整版（30 分）**：再加發牌統計（每一次訊號的品質）與蒙地卡羅（消除運氣）。」

沒回答 → **走快版先交**，交完再問要不要加。⛔ 不要自己加菜。

#### ⭐ 第一順位：雪鴞（課程送的資料庫，全市場 2,800 檔一次到位）—— 有裝就先用它，沒裝才走上面的本機資料／yfinance

```
 使用者說「用雪鴞的資料」，或 DATA_SOURCE.md 的「雪鴞」段有寫 .env 位置
        │
        ├─ .env 位置沒寫 ──→ 問：「你的雪鴞安裝包資料夾在哪？裡面有一個 .env」
        │                    → 問到寫回 DATA_SOURCE.md 的「雪鴞」段（只記路徑，不記帳密）
        ▼
 用「裝雪鴞的那個環境」的 python 跑 scripts/load_snowyowl.py
   px = load_panel_from_snowyowl(r"<.env 路徑>")      ← 回傳格式跟 load_panel() 一模一樣
   之後從 Step 1 起完全相同
```

⛔ **三件事一定要守**
1. 帳密由 `load_snowyowl.py` 自己讀 .env —— **AI 不准 Read／cat 那個 .env、不准叫使用者在對話框打帳密**
2. 雪鴞只吃 Python 3.11–3.12，要用裝雪鴞的那個環境跑（不確定在哪就問使用者，不要猜）
3. 雪鴞只有目前還在市場上的公司 → **存活者偏差**，報告一定要寫；
   資料約 4 年（1,000 個交易日），「樣本期數」多半落在黃燈，老實講「參考值」

第一次跑會比較久（它要下載五個矩陣），先跟使用者說一聲。

**因子驗證需要「很多檔」，不是一檔。** 至少 100 檔才有分組的意義；
只有 20 檔就老實說「樣本太少，這個結果參考就好」。

比喻：你要比較「前十名跟後十名」，班上只有 6 個人的話，這句話本身就沒意義。

### Step 1：把想法寫成一個分數

使用者說的是人話，你要把它變成**每一檔、每一天都算得出來的一個數字**。

| 使用者說 | 寫成分數 | 注意 |
|---|---|---|
| 「站上季線的比較會漲」 | `收盤 ÷ 60日均線 − 1` | 用連續值不要用 0/1 —— 0/1 只能分兩組，看不出單調性 |
| 「最近很強的會繼續強」 | 過去 12 個月報酬（跳過最近 1 個月） | 跳過最近一個月是慣例，避開短期反轉 |
| 「爆量的隔天會續漲」 | `近 5 日均量 ÷ 近 60 日均量` | 分母要夠長，不然量能一動整排都動 |
| 「接近前高的比較會突破」 | `收盤 ÷ 過去 52 週最高 − 1` | ⚠️ 這個會大量同分在 1.0（很多檔同時創高）→ 技術紅線 C 必做 |
| 「跌深的會反彈」 | `−（過去 20 日報酬）` | 記得取負號，讓「分數高＝你認為會漲」 |

**規則**：分數的方向一律是「**數字越大 ＝ 你認為越會漲**」。
方向弄反的話，整張報表的多空會顛倒，而且看起來像因子無效。

`scripts/factor_lib.py` 有 8 個只用日線就能算的公開因子可以直接抄。

### Step 2：分組跑報酬 ＋ 打燈

跑 `scripts/factor_test.py`。它會：

1. 每期把所有股票**按分數排序、切五組**（同分同組，崩組也不會丟資料）
2. 算每組下一期的報酬（**收盤算分數、隔天開盤進場**）
3. 算多空價差（最強組 − 最弱組）
4. 算 IC（分數跟下期報酬的秩相關）與 ICIR（IC 均值 ÷ IC 標準差，看穩不穩）
5. 打燈

⛔ **分組階梯（單調性）是最重要的一顆燈。** 把股票按分數切五組，第 1 組到第 5 組的報酬要**階梯式一路往下走**
（或反過來一路往上）—— 這才代表「分數越高越會漲」是規律，不是幾檔飆股撐出來的。**階梯不成立，其他燈再綠也不能信。**
⛔ **術語對照：課堂上叫它「IQR」**。聽到「IQR」「階梯」就是在講這個，先把分組報酬的階梯圖拿出來。
ICIR 是第二重要：IC 均值告訴你「平均猜得多準」，ICIR 告訴你「每個月都這麼準、還是偶爾神準偶爾亂猜」。

**燈號表**（門檻是學術與業界慣例，不是誰的私房數字）：

| 指標 | 國小生比喻 | 🟢 綠 | 🟡 黃 | 🔴 紅 |
|---|---|---|---|---|
| **分組階梯（單調性）** ★ | 五組是不是階梯式往下（最重要，課堂上叫 IQR） | ≥ 0.8 | 0.5–0.8 | < 0.5 |
| 多空價差年化 | 前 10 名比後 10 名高幾分 | ≥ 8% | 3–8% | < 3% |
| **Sharpe** | 一路穩，還是一路急煞 | ≥ 1.0 | 0.5–1.0 | < 0.5 |
| **Sortino** | 只算急煞的版本 | ≥ 1.5 | 0.8–1.5 | < 0.8 |
| IC 均值 | 猜名次猜得準不準 | ≥ 0.04 | 0.02–0.04 | < 0.02 |
| ICIR | 猜得穩不穩 | ≥ 0.5 | 0.3–0.5 | < 0.3 |
| 勝率 | 10 個月有幾個月賺 | ≥ 55% | 50–55% | < 50% |
| 最長連虧 | 你要忍多久 | ≤ 6 個月 | 6–12 | > 12 |
| 樣本期數 | 骰子丟了幾次 | ≥ 60 | 36–60 | < 36 |

⛔ **Sharpe 與 Sortino 兩個都要看、兩個都要打燈**，不是二選一。
兩個燈不一致就明說差在哪：「Sharpe 綠 / Sortino 黃 → 整體報酬夠、但跌的時候比較痛」。

⛔ **單調性比多空價差重要。** 價差大但不單調（例：第 1 組最好、第 3 組第二好）
通常代表結果被幾檔極端值撐起來，換一段時間就散掉。

### Step 3：發牌統計（完整版才做）

**這一層在問：不管你怎麼配資金，這個因子「發出來的每一張牌」品質好不好。**

```
 發牌層（訊號本身）                   資金層（配了錢之後）
 ├ 每單期望超額（扣成本、減大盤）      ├ 組合報酬曲線
 ├ 勝率                              ├ 最大回撤
 ├ 風報比＝平均賺 ÷ 平均賠            └ 會被「容量、順序、運氣」污染
 └ 年訊號量
        └─── 先看這層再看那層 ───┘
```

比喻：**發牌層是「這副牌好不好」，資金層是「你這局打得好不好」。**
牌好但打輸，可能是打法問題；牌爛卻打贏，那是運氣，下次不會再有。

跑 `scripts/signal_quality.py`。它會給：

- **每單期望超額**：每次因子叫你買、持有到下期，平均比大盤多賺幾%
- **勝率／風報比／年訊號量**
- **逐年牌品**：品質是每年都有，還是靠某一年？最差的一年有多差？
- **前 5 筆占總超額的比重**：> 50% 🔴 這個因子是靠幾筆神跡撐起來的

⛔ **前半段為負、後半段很好的因子，一票否決。** 那是撿到的，不是找到的。

### Step 4：蒙地卡羅（完整版才做）

把所有單筆結果丟進袋子裡**有放回地重抽 5,000 次**，重組出 5,000 個平行時空。

比喻：**同一副牌，重新洗 5,000 次再打一遍。** 如果只有 3,000 次會贏，
那上次贏很可能只是牌順，不是你會打。

輸出：
- 贏過大盤的機率（< 60% 就不要說這個因子有效）
- 年化超額的 P5 / P50 / P95（P5 是「運氣很背的那個版本」，那才是你要能接受的）

## 五大陷阱（每次都要掃一遍）

詳見 `references/five-traps.md`。摘要：

| 陷阱 | 比喻 | 症狀 | 怎麼查 |
|---|---|---|---|
| **未來值** | 先偷看答案再作答 | IC 高得離譜（> 0.15）、單調性完美 | 分數用到的每個欄位，問「這個數字什麼時候才知道？」 |
| **同分偏誤** | 同樣高的人被插到前面那排 | 某因子突然變好、而且分數有大量重複值 | 看每組的檔數是不是剛好整除 → 是的話你八成用了 `method="first"` |
| **崩組丟資料** | 喊第五排，但那排根本沒人 | 12 個月報酬「剛好 0.0000」 | 看報酬表的 NaN 期數 |
| **存活者偏差** | 只統計還在班上的人 | 報酬好得不合理，尤其小型股因子 | 你的資料裡有沒有已經下市的公司？沒有就要說出來 |
| **過擬合** | 這把鑰匙只能開這一扇門 | 換一個參數（60 日改 55 日）結果就垮 | 參數 ±20% 掃一遍，看是一片高原還是一根針 |

## 常見問題

**Q：我只有 30 檔股票的資料，能驗嗎？**
可以跑，但分五組每組只有 6 檔，隨機性很大。老實跟使用者說「這是參考值，不是結論」，
並問要不要用 yfinance 補到 100 檔以上。

**Q：因子紅燈就一定沒用嗎？**
不一定，但**不要當主訊號**。紅燈因子有時候是好的「濾網」（單獨用沒 alpha、
但拿來排除危險標的有效）。想確認就把它當條件、看它能不能讓一個綠燈因子變更好。

**Q：多空價差是正的，但我不能放空，這樣有意義嗎？**
有，但要分開看：報表會同時給「只做多的那一組報酬」與「多空價差」。
只能做多的話，看「最強組 − 大盤」而不是「最強組 − 最弱組」。

**Q：驗完之後呢？**
綠燈或多數黃燈 → 用 `backtest-review` 把它做成完整策略（加進出場、停損、成本）再驗一次。
**因子有 alpha ≠ 策略會賺錢** —— 中間還隔著交易成本、容量、與你抱不抱得住。
