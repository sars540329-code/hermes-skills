檔名：`<日期 YYYY-MM-DD 或 YYYY-MM> <報告名稱>.md`（Windows 不能用的字元 \ / : * ? " < > | 換成全形）

```markdown

報告日期: <日期；內文資料截至哪天也寫>

# <報告名稱>

> 這是 AI 讀完報告後，用自己的話整理的重點與推論邏輯。觀點屬於 <機構>，不是本筆記的看法，也不是投資建議。數字與圖表以原文為準。

## 5W1H 總覽
| | |
|---|---|
| **Who 誰說的** | [[機構]] 哪個單位 |
| **What 核心主張** | 一到兩句 |
| **When 時間** | 發布日、資料截至日、報告提到的關鍵時間點 |
| **Where 哪個市場** | 國家、資產類別 |
| **Why 為什麼這樣看** | 列出 2～4 個核心理由 |
| **How 怎麼推論** | 用了哪些數據、方法、歷史樣本 |

## 報告的推論主線
（用箭頭圖畫出：前提 → 推論 → 結論。讀者看這張圖就知道整份報告在講什麼。）

## 分章重點
### <章節名>（p.X–Y）
- **結論**：
- **為什麼**：推論鏈，一步一步寫
- **證據**：數字＋日期＋資料來源（報告自己引用的來源也要寫）
- **風險／例外**：報告自己提到的

## 提到的個股
依市場分組，全部做成 [[連結]]

## 待驗證
- 【待驗證】樣本太少、用預估值、前後矛盾、看不懂的地方
```

## 寫得夠細的標準
- 每一章至少有一個具體數字與日期。
- 「為什麼」要寫到讀者能復述推論，不能只寫結論。
- 表格型的內容（例如燈號表、機率表）改寫成條列，保留分類與結果，不要截圖或原樣複製。
- 20 多頁的月報大約寫成 150～300 行；幾頁的快訊就寫短一點，但 5W1H 一樣要有。
