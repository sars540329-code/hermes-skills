# To Obsidian

把「別人的研究」變成「你自己找得到、接得上的筆記」。**每一步都要等使用者點頭才往下走，不要一口氣做完。**

```
 ① 問：Obsidian 在哪？要追哪些網址？
        ▼
 ② 看你的 Obsidian：現在怎麼分類、連結怎麼命名、標籤怎麼用、有沒有索引頁
        ▼
 ③ 看網站：走哪條路（A／B／C）、有哪些文件和分類、多久更新、版權怎麼說
        ▼
 ④ 提案：資料夾怎麼分、筆記長怎樣、哪些東西做成 [[連結]]、怎麼跟你既有筆記串 ── 等使用者同意
        ▼
 ⑤ 試抓：每個分類抓最新 1 份，寫成筆記給使用者看 ── 等使用者說 OK
        ▼
 ⑥ 問：要不要加入每天／每週自動跑的排程？
```

工具都在 `scripts/tool.py`（指令說明在檔案開頭）。缺 `requests` 就先 `pip install requests`。

## 第一次使用

### ① 問兩件事（一次問完）
1. 「你的 Obsidian 資料夾在哪裡？」（Obsidian 左下角『管理儲存庫』看得到路徑）
   ⛔ 使用者回答之前，**不准自己去電腦裡找 Obsidian、不准掃任何資料夾**；之後也只掃使用者給的那一個資料夾。
2. 「你想定期追哪些網址？」可以一個或多個。

### ② 看使用者的 Obsidian（先讀懂他的習慣，再提案）

跑 `python scripts/tool.py vault <Obsidian 資料夾>`（只讀、不改任何檔），看：

| 看什麼 | 用來決定 |
|---|---|
| 資料夾怎麼分（前兩層、各有幾篇） | 新筆記放哪：有現成的「研究」「報告」「交易」類資料夾就放進去，不要另開頂層 |
| 索引頁（總入口、_索引、MOC、總覽） | 新筆記要不要登記進某個索引頁，照它原本的格式加一列 |
| 最常被連結的頁面 | 同一個東西沿用他已經在用的名字 |
| 連結命名習慣（名稱／代號＋名稱／路徑式） | 新連結照同一種寫法 |
| 常用標籤、筆記開頭屬性 | 新筆記的 tags 與屬性欄位照他的習慣 |

必要時再開一兩篇他同類型的筆記（例如既有的研究報告筆記）看格式。**提案要說明「我照你原本的哪個習慣」，而不是另起一套。**
使用者的 Obsidian 是空的或很少筆記：就用本 Skill 的預設（`references/note-template.md`、`references/linking-rules.md`）。

### ③ 看網站：先判斷要走哪條路

每個網址先跑 `python scripts/tool.py links <網址>`，看結果裡的 `route`：

```
 A  可以直接抓        → Python 抓清單、下載文件。快、便宜、排程最穩
 B  要瀏覽器才看得到   → 內容要 JavaScript 才顯示：用瀏覽器打開再讀
                        （Claude 內建瀏覽器，或 Claude in Chrome）
 C  要登入            → 用「使用者自己已經登入的 Chrome」去讀（Claude in Chrome）
                        ⛔ 不問帳號密碼、不幫忙輸入密碼、不存任何帳密
                        ⛔ 先看服務條款：條款禁止自動抓取或轉載 → 不抓，跟使用者說明原因；
                           條款允許才用這條路
```

- `route` 只是初判，**最後以實際讀到的內容為準**：A 卻讀不到東西就改走 B；B 一打開就是登入頁就改走 C。
- `kind` 是 `documents`（PDF 等文件）或 `articles`（網頁文章列表）。文章類的清單會混進選單連結，自己挑出真正的文章。
- 網站本身有分類（例如分頁、欄目）就照它分；同一個網站常常不只使用者給的那一頁，發現其他分類要主動問要不要一起追。
- 提案裡一定要寫出每個來源走哪條路，以及對排程的影響：
  - A：排程最穩
  - B：排程時 Claude 要開瀏覽器，比較慢、比較耗額度
  - C：排程時 Chrome 要開著而且登入沒過期，任何一個斷掉就會失敗；建議頻率放低，或改成手動跑
- 挑最新 1 份下載來讀（`tool.py download`），**一定要看文件最後的免責／版權聲明**。
- 讀 PDF：先用 Read 工具直接讀；讀不到就 `tool.py pdftext <路徑>`（需要 `pip install pypdf`）。

### ④ 提案（照這個格式，等使用者同意）

```
📚 我看完了：<網站名稱>
- 有 N 個分類、約 M 份文件、大約多久更新一次
- 讀取方式：A／B／C（原因）
- 版權：<照實寫它怎麼說，例如「禁止引用、重製、轉寄」>

📂 你的 Obsidian 現在是這樣：<資料夾結構重點、索引頁、連結命名習慣、常用標籤>

📁 資料夾：<照你的結構接上去>/<來源名稱>/<照網站的分類>/<日期 報告名>.md
   索引：<要登記進哪個索引頁，或不登記>

📝 筆記格式：5W1H 總覽 → 推論主線圖 → 分章重點（結論／為什麼／證據）→ 提到的個股 → 待驗證
   （格式見 references/note-template.md）

🔗 連結方式：
- [[雙向連結]]：公司、國家、產業、概念、指標、人名、機構 —— 例：[[台積電]] [[HBM]] [[美債殖利率]]
- #標籤：來源與報告類型、大主題 —— 例：#富邦研究 #投資月報 #總經
- 我在你的 Obsidian 找到這些已經存在的頁面，會沿用同樣的名字：<列出 5～10 個>

🔒 版權處理：只寫重點整理與原文連結，不複製原文段落與圖表；原檔只留在本機快取（~/.to-obsidian/cache），不放進 Obsidian

要照這樣做嗎？想改哪裡直接說。
```

- 同一個東西沿用使用者已經在用的名字（從 ② 的統計挑；不確定的用 Grep 在他的 Obsidian 裡查一次）。連結規則見 `references/linking-rules.md`。
- 使用者同意後，把設定寫成 JSON 檔再跑 `tool.py config-set <檔案>`（新增來源時工具會自動跟舊設定合併，同名來源會被更新，不會把舊的整份蓋掉）：
  ```json
  {"vault": "<Obsidian 路徑>",
   "sources": [{"name": "富邦研究報告", "url": "<網址>", "route": "A", "folder": "富邦研究報告/全球外匯週報", "tags": ["富邦研究", "外匯週報"]}],
   "approved": "YYYY-MM-DD"}
  ```

### ⑤ 試抓
- 每個來源抓**最新 1 份**，照 `references/note-template.md` 寫成筆記、存進設定的資料夾。
- 寫完用 `tool.py mark <來源名稱> <網址>` 記起來，之後不會重抓。
- 給使用者看：筆記完整路徑、裡面做了哪些 [[連結]]、哪些接上了他原本就有的頁面。
- 問：「內容夠不夠細？連結方式要不要調？」有修改就照改，改到他說 OK。

### ⑥ 問要不要加入排程
使用者說 OK 後主動問：「要不要把它加入排程，之後自動抓新報告？」要的話，用 Claude Desktop 的排程任務（Routines）建立，頻率照網站更新速度建議（週報一週一次、日報一天一次），排程裡放這句：

```
用 to-obsidian 檢查我追蹤的網站有沒有新文件，有的話整理進 Obsidian，跑完回報新增了哪幾份、寫進哪裡。
```

建好後提醒：先按一次「立即執行」、權限選「永遠允許」；排程時間 Claude Desktop 要開著、電腦不能休眠。

## 之後每次（手動或排程）

1. `tool.py config` 讀設定；沒有設定就回到「第一次使用」。
2. 每個來源照設定的讀取方式（A／B／C）取得清單 → `tool.py new` 找出沒收過的。
   走 B／C 的來源，打不開或登入過期時，回報「這個來源這次沒抓到、原因」，不要卡住整輪。
3. 一份一份：下載 → 讀完整份 → 照模板寫筆記 → `tool.py mark`。
   - 一次最多處理 5 份；更多的留到下一輪，回報時說還剩幾份。
4. 回報：新增了哪幾份（完整路徑）、這次新出現的 [[連結]]、抓不到或讀不到的原因。

## 筆記的硬規則

- **細節不能丟**：數字、日期、資料來源、推論順序都要在。讀者只看筆記，要能說出「他們為什麼這樣看、根據什麼」。
- **5W1H 一定要有**：誰說的、主張什麼、什麼時候、講哪個市場、為什麼、怎麼推論與證據。
- **觀點歸屬要清楚**：寫「報告認為…」「報告的配置看法…」，不寫成像是自己的判斷。
- **不給建議**：不寫「應該買／賣」「進場」「出場」「逢低布局」，**連描述市場資金動向時也不用這些詞**（改成「資金回流」「拉回時買盤進來」）；報告原文有建議語氣，改寫成「報告的看法是…」「報告認為值得關注…」。
- **版權**：見 `references/copyright.md`。只寫自己的話整理的重點＋原文連結；不整段複製、不貼原文圖表；原檔只存在本機快取（~/.to-obsidian/cache），寫完筆記就可以刪。
- **看不懂或跟前後文矛盾的地方**，寫進「待驗證」，不要自己補。
