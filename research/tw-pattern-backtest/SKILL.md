# 台股型態／進場條件驗證

用途：使用者問「這個型態有沒有用／勝率如何／加某濾網會不會更好」（活動靶、穿雲劍、飄旗、籌碼濾網等 0/1 訊號）。連續因子改用 `factor-check`。使用者出場規則與閘門見 `tw-technical`，型態定義見 `ma55-main-rise`。

## 常駐規則

1. **一定要有同日隨機對照組。** 使用者出場規則（收盤破日21MA 或 -5%）本身就有正期望值（勝率約 30%、風報比 3~4），不對照就會把出場的功勞算給進場型態。對照＝同日期、同檔數、同流動性池、同出場規則，重抽 15~30 次取平均。
2. **大盤濾網（加權指數>55MA）會拉高任何進場的報酬。** 要比「訊號−隨機」而不是絕對平均，否則濾網的功勞會被算成型態的。
3. **宣稱「有效」前必列四項：** 蒙地卡羅贏隨機機率≥8 成、拿掉前 5 筆最賺的仍優於隨機、時間樣本外仍有優勢、逐年「訊號−隨機」弱勢年不崩。未全過一律說「候選清單，不等於已驗證」。
4. **勝率分「全部／已出場／持有中」列出。** 持有中樣本少且偏樂觀，不要併進總勝率。
5. **不要用挑出的贏家當證據。** 使用者截圖例子都是事後大贏家，只能校準偵測器，且要說「門檻是對著例子調的」；回測拿校準年以前當時間樣本外。
6. **只測手上有資料的東西。** 主力／分點／籌碼鎖定率需要券商分點歷史，免費公開來源沒有；不用三大法人假裝主力，若用一律標「替代測試」。改成給使用者 XQ 腳本，開／關籌碼開關各回測一次。
7. 使用者的說法與數據衝突時（「小型股最容易出現」「有主力買勝率才高」「日55 原則」）：照實測、把數據並排、讓使用者決定，不迎合也不硬駁。
8. 回覆用繁體中文，結果表先行、限制在後，結尾給一個明確下一步。使用者偏好一步一步、具體指令。

9. **使用者提出可檢定的假說時，把它拆成可操作的對照，不要只做「有／無條件」的二分。** 例：「週確認才算有效突破」要比的是「日訊號隔日進場」vs「週末確認後隔週進場」，並標註進場價變貴的成本；「未確認組」含已失敗的訊號，其差只能說明機械效果。
10. **籌碼三指標（主力集中度＝主力買賣超÷成交量、籌碼鎖定率＝主力買超÷(發行−董監持股)、股本比＝主力買超÷總股本）分子相同、只差分母，不是三個獨立證據。** 小型股股本小時三者會一起偏高；解讀名單時別把「三個都高」當三倍證據。名單網路上給的門檻（>20%、>2%、1%~4%）找不到出處，不當標準。

11. **所有濾網與流動性門檻只能用「決策當下已知」的資料。** 篩選用進場日當天的量＝偷看未來，會把優勢灌水（曾使一組結果從 57% 虛報成 70%）。要用 XQ 腳本實際會讀的定義（例如 `Average(Volume,5)[1]`）。
12. **XQ 腳本的實際執行時點常比回測晚。** 日線腳本要到週一才讀得到上週週K，進出場都晚一個交易日；回測要多跑一版「晚一天」，優勢通常明顯縮水。週線頻率的腳本（週K收完、下一週開盤進出）時點與回測一致，但無法用日停損，只能用週收盤停損。
13. **提高成交量門檻會同步抬高隨機對照。** 比「訊號−隨機」與蒙地卡羅，不要拿絕對平均報酬說門檻越高越好（門檻只是把股池換成強勢大型股）。
14. **使用者要「分階段／避開末升段」時，要求他給失敗案例，不要只收贏家。** 贏家標籤（初升、主升）全都落在同一批大漲股，單一閾值（例如距週55MA 乖離≥100%）會誤殺其中的成功案例；以組合條件加使用者標籤確認。
15. **要用某指標當條件前，先用使用者查價框的數字反推 XQ 的算法。** 對價格序列（收盤／加權收盤 (H+L+2C)/4／典型價）×均線型態（EMA／SMA／Wilder）做格點搜尋，取誤差最小者並逐點對照。XQ 的 MACD（DIF8-21、MACD5）＝加權收盤價的 EMA8−EMA21、訊號線 EMA5，9 個查價框數字完全吻合；用一般收盤價會差 6%。
16. **「這輪第幾次突破」要用完整的突破條件計數。** 粗略計數（只看站上邱55的次數）測不出差異，用完整邱3盤條件計數才看到第3次以後轉負。定義不同結論就不同，報告要寫明定義。
17. **使用者的截圖範例要先對照條件。** 把查價框數字（均線、均量箭頭↑↓）逐項對使用者口述的條件；範例自己不符合（例如「均線全向上」但 SMA55 是↓）時，兩個版本都跑並說明範例落在哪一版，不要默默挑一個。跟 XQ 對數時：量、均量應完全一致；價格類差幾 % 是還原價 vs XQ 原始價。
18. **股池排名要用當時的資料（每月用當月成交量／成交金額重排前 N），隨機對照也從同一個月的同股池抽。** 使用者說「權值前 100」時先問要當時名單還是現在名單（現在名單＝倖存者偏差）。用「張」排名偏向低價股，成交金額排名才接近權值股；換股池時隨機對照會一起變好，結論看「訊號−同池隨機」。
19. **出場週期要跟進場週期一致。** 月線突破配日 21MA／−5% 出場，平均只抱約 11 個交易日就被洗掉、等於隨機；月線進場用月線出場（如月收破前 3 根低），要測使用者日線出場就並列比較。
20. **「整體獲利／獲利曲線」的交付格式固定**：未出場的以資料最後一天收盤強制出場（下市／停止交易的另標「停止交易、最後收盤出」）、扣手續費 0.1425%×2＋證交稅 0.3%、毛／淨分列；100 萬、同時最多 3 檔的資金曲線（年化、最大回撤與起訖月份）＋實際買進的交易表；一定附「獲利集中在哪幾筆、期末淨值幾成來自最後一段、路徑依賴」。做法見 `references/procedure.md` 第 7 節。
21. **回測跨年或用月線一律用除權息還原價**（`E:\XQOWL\tw_daily_fetch\data\panel_adj.parquet`，2016 起、含已下市股）；做法與驗證見 tw-chips-data 的 `references/daily_quotes.md`。月 SMA55 需約 4.6 年歷史，訊號最早從資料起點後 55 個月開始；當月未收完的月 K 不當訊號。

## 流程

完整步驟見 `references/procedure.md`：建股池（TWSE＋TPEx 清單、yfinance 批次、背景執行）→ 事件研究（t 收盤判定、t+1 開盤進場）→ 對照組＋蒙地卡羅（以月為單位重抽）→ 截圖校準偵測器（`diag` 記錄每關擋掉原因）→ 交付 XQ 腳本。
已得結果（穿雲劍、飄旗、週21MA 活動靶、大型 vs 小型、階段分組、寶塔線出場、資金模擬、成交量門檻、腳本時點、校準例）見 `references/results.md`。出場比較與資金模擬的做法見 `references/procedure.md` 第 5、6 節。

## 常見坑

- **在 `execute_code` 裡用 `exec(open(舊腳本).read())` 重用腳本時，腳本內的 `sys.stdout.reconfigure(...)` 會因輸出物件不支援而丟 AttributeError。** 把重用的程式碼寫成獨立 .py 檔、用 `subprocess.run(["python", 檔])` 跑並擷取 stdout；長回測不要塞在單一長時間前景呼叫。
- 報告標籤要對單位：回測內部的持有天數是**交易日**，別寫成日曆天；週腳本的流動性是「週量/5」，與日腳本的 5 日均量略有出入（事件數差約 1%）。
- 只回報真的跑過的比較。要並排比較多個門檻卻沒跑成時，明講「這部分沒有結果」，並列出手上僅有的、定義不同的數字，不要用舊數字湊表。

- **驗證用 Python 重現 XQ 腳本時，「找最小值」的初值不可用固定大數（如 999999）。** yfinance 成交量單位是股，數值常 >999999，`min(初值, 量)` 永遠停在初值，使「凹洞量」之類條件被錯判成立（曾因此與回測寫法差 65 筆，誤以為 XQ 邏輯有出入）。XQ 的量單位是張，大量股（如群創週量中位 29 萬張、最大 646 萬張）同樣可能超過 999999。初值一律取第一個元素：`faceVolMin = wkV[1]`、`faceLow = wkL[1]`。價格類的最小值初值用 999999 則安全。
- 兩套實作結果有差異時，先逐條列出同一筆資料上每個條件的真假、再比較中間變數與資料單位，不要先猜邏輯錯；差異常來自驗證程式自己的資料尺度，而不是被驗證的腳本。
- XQ 週線腳本用「往回第 i 週」取值：`[0]`＝本週（盤中未收完）、`[1]`＝上一個已收完的週；週選股要在週五收盤後跑。未在 XQ 編譯前須明說，並附檢查點：「執行日期選標準例買點週的週五，結果應含某股」。

- 歷史資料太短會讓週線條件默默判「不成立」，誤判成「腳本和偵測不一致」；週55MA 的驗證資料至少抓 3 年。
- 回看視窗內有 NaN（新上市／停牌）會讓 `nanargmax/nanargmin` 丟例外；進迴圈前先整日跳過有缺值的視窗。
- 空 DataFrame 用布林遮罩會被當成欄名選取；空結果先把布林欄位 `astype(bool)`。
- XQ 副圖標題列的數字是最新一根 K 棒，不跟游標走；要讀某天用「查價框」。用「主力÷成交量＝比例」和對 yfinance 的量、均量驗證是哪一天。
- XQ 是未還原價、yfinance 是還原價，絕對價差數 %，比例相同，不影響型態判定。
- 週線圖上「05/04」這類標記是該週起點，買點日可能是週內某天，要跟使用者確認。
- Hermes 端沒有 XQ 編譯器：用 Python 逐行重現腳本邏輯驗證，明說「未在 XQ 編譯」，附「執行日期選 X，結果應含某股」的檢查點；完整腳本要整份貼在回覆裡，不要只給 diff 截圖（使用者會誤以為截圖就是腳本）。
- 日線腳本裡用變數當索引的 `GetField("收盤價","W")[i]`、`Average(Close,55)[i]`、`Array: x[80](0)` 已在 XQ 編譯通過，不必再預警；真正的風險是**全市場執行逾時**：在每根 K 棒都讀上百筆週資料會回「系統錯誤／連線逾時」。腳本一律「先算便宜的日線條件，成立才讀週線」，週資料只讀約 80 週，`SetTotalBar` 隨之縮小；邏輯不變，用 Python 重現確認標準例仍全命中再交付。
- XQ 選股回「系統錯誤(0)／連線逾時(2)」時，不要猜是哪個欄位：先把主力等額外欄位關掉排除，再縮腳本運算量；左下「開啟 Log」常是灰的按不了，別依賴它。
- 使用者貼進編譯器的內容若含檔案路徑、`@@`、`+` 開頭行，代表複製到的是聊天的檔案卡片／diff 而不是程式碼；錯誤訊息裡出現 `AppData`、`hermes`、`skills` 就是這個徵兆。交付時一律把完整程式碼貼在回覆的 code block 裡，並說「清空後整份貼上」。
- 交付後以「XQ 選股執行日＝標準例買點日」驗證：用同一天、同一批資料跑 Python 重現，比對選出代號與旗桿漲幅（本次 10 檔完全一致；Python 多出的邊緣股是成交量門檻附近、XQ 與 yfinance 量差約 1%）。
