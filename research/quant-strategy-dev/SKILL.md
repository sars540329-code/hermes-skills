# 量化策略開發方法論（學員版）

> 適用任何市場、任何頻率的量化策略開發。
> 學員版以**雪鴞**為主要資料來源；方法論本身跟資料源無關，換成自己的 CSV 也一樣走。

---

## 🟢 第一次用？先看這裡

**這個 skill 在做什麼**：你說一句「我覺得 XX 會漲」，它陪你把這句話變成一個**可以回測、可以驗證、可以抓出自己錯在哪**的策略。
重點不是跑出漂亮數字，而是**確定那個數字是真的**。

**七個步驟，一步一句話**：

| 步驟 | 在回答什麼問題 |
|---|---|
| **0 資料檢查** | 手上的資料夠不夠、乾不乾淨？（⛔ **永遠不跳過**） |
| 1 假設形成 | 用一句話講清楚：「當 X 發生時，Y 比較容易發生」 |
| 2 單因子驗證 | 這個條件**單獨**拿出來，有沒有用？（可以交給 `factor-check`） |
| 3 回測引擎驗證 | 回測程式本身有沒有偷看答案、成本有沒有扣？ |
| 4 參數優化 | 停損停利、週期怎麼設？找「一片高原」而不是「一根尖峰」 |
| 5 組合與濾網 | 多個條件怎麼疊？濾網是用來排除危險，不是只挑安全 |
| 6 穩健性驗證 | 換一段時間、換一種切法，它還站得住嗎？ |

做完七步之後還有兩個收尾：**資金管理**（每次下多少）與**交付前檢查**。

**AI 開工時會先做兩件事**：
1. **先問你資料在哪** —— 讀 `DATA_SOURCE.md`，還沒設定就問你雪鴞的 .env 放在哪（只記位置，不記帳密）。
2. **先跑 Step 0 資料檢查** —— 不管你多急，這一步都不跳。資料錯了，後面每個數字都是錯的。

**兩種交付，第一次先走基本版**（詳見 § 四）：

| | 基本版（每次都有） | 完整版（AI 會問你要不要） |
|---|---|---|
| 內容 | 五指標燈號表、`trades.csv`、P&L＋回撤圖、回測配置說明 | 互動式交易明細、肥尾檢查、時間集中性、滾動檢驗、IS/OOS、WFA、12 模型蒙地卡羅、Word 報告 |
| 時間 | 幾分鐘到十幾分鐘 | 可能要一小時以上 |

⛔ **不管哪一版，下面五條紅線都必做**：不偷看未來（look-ahead）、訊號隔天開盤才進場、同分同組、一字漲跌停不能假裝成交、成本要扣（而且要保守地多扣）。

## 一、核心原則

1. **先驗證單因子，再組合** —— 沒驗證過的因子加在一起＝雜訊＋雜訊。
2. **回測引擎先做對，再做快** —— 偷看未來的資料（look-ahead bias），會讓假績效看起來像真的。
3. **停損停利參數＞訊號參數** —— 出場方式對結果的影響，往往比進場訊號本身還大。
4. **用數據說話，不用直覺猜** —— 每個假設都要跑數字驗證。
5. **決策必留回測依據（Decision Log）** —— 任何不是一眼就懂的參數選擇（冷卻機制、部位大小、濾網門檻、權重方法…），都要：
   - 跑 ≥ 3 個替代方案的回測對照表
   - 記錄日期、考慮過的選項、最後的選擇、**依據的資料檔**
   - 寫進專案裡的 `docs/decision_log.md`（或等效文件）
   - 完整版 Word 報告 § 9 附「替代方案對照表」，讓讀者看到「為什麼不是別的」
6. **訊號品質先於資金績效** —— 策略評估分兩層：「發牌層」（每一筆訊號本身的品質，跟資金怎麼配無關）與「資金層」（組合回測，會被容量、時機、運氣汙染）。**排序與取捨先看發牌層** —— 資金層好，可能只是時機剛好；發牌層好，才是本質。詳見 § 五。

## 二-B、資料來源：雪鴞優先

### 開工第一件事：讀 `DATA_SOURCE.md`

- 還是「尚未設定」→ **開口問使用者**雪鴞安裝包在哪（裡面有 `.env`）、裝雪鴞的 python 在哪，問到就寫回去。
- ⛔ 只記路徑，**不記、不念、不貼帳號密碼**。帳密只在 `.env`，由 `scripts/load_snowyowl.py` 自己讀。
- ⛔ 雪鴞要用「裝雪鴞的那個 python 環境」跑（課程學員包裝的是 Python 3.13；較舊的安裝包是 3.11–3.12）。⛔ 版本號跟這裡寫的不一樣也**不要重裝** —— 那個環境能 `import snowyowl` 就對了。所有腳本都用同一個 python 跑。

```python
import sys; sys.path.insert(0, r"<本 skill 資料夾>\scripts")
from load_snowyowl import load_panel_from_snowyowl, load_symbol_from_snowyowl

px  = load_panel_from_snowyowl(r"<.env 路徑>", freq="月")     # 全市場月 K（每月換股策略）
one = load_symbol_from_snowyowl(r"<.env 路徑>", "2330")       # 單一檔日 K
```

### 雪鴞的五個關鍵事實（⛔ 寫程式、寫報告前都要記得）

| # | 事實 | 影響 |
|---|---|---|
| 1 | **`api.MSMP.日_K` 只有約 1000 個交易日（≈ 4 年）** | 日頻策略的回測窗口最多 4 年；要更長的歷史必須降頻 |
| 2 | **`api.MSMP.月_K`／`週_K` 從 2012 年 1 月開始**（2026-09-30 實測；用前仍先印出第一根確認），而且有 `adj_Open`、`adj_Close`（還原價）、`市值_百萬`、`成交額_百萬` | 每月／每週換股的策略用這兩張，可以拉到 10 年以上 |
| 3 | **成交量單位是「張」，不是「股」** | 流動性門檻（例：日均量 ≥ 1000 張）直接用張比；要跟「股」為單位的程式混用，先 ×1000。`load_snowyowl.py` 兩個都給：`volume_lots`＝張、`volume`＝股 |
| 4 | **名單以目前還在市場上的公司為主** | **存活者偏差**（已經下市、倒掉的公司不在裡面，歷史績效會偏好看）。⛔ 報告**必須寫出來**，不准省略 |
| 5 | **定期換股＝月底收盤算訊號、下個月第一個交易日開盤成交** | 用月 K 時，就是「**下一根**月 K 的 `adj_Open`」（見 § 三-3-bis） |

另外：
- 算報酬用**還原價**（`adj_*`，已處理除權息）；判斷**一字漲跌停**用**原始價**（`raw_*`）—— 還原價在除權息日前後的漲跌停價位對不上。
- 雪鴞文件寫月 K／週 K 約 2014 年底起，但實測 `MSMP.月_K` 第一根是 2012-01。以實際印出來的為準。
- 月 K 的日期標籤不一定是月底（例如 5/7、6/1），但價格是那個月的正確開收盤，用「第幾根」對齊就好，不要用標籤日期去算天數。
- ⛔ **月 K／週 K 的最後一根可能還沒收完**（月中跑，最後一根就是「這個月到今天」）。算月底訊號前，先確認最後一根的日期是不是真的月底，不是就丟掉。
- 雪鴞本身還有積木選股與回測引擎；本 skill 只用它當**資料來源**，回測邏輯自己寫、自己驗（這樣才看得到每一個成交假設）。

### 財報與月營收：日期是「所屬期間」，不是「公告日」（紅線）

**任何資料來源都一樣**：財報、月營收的日期欄位，幾乎都是「這份資料屬於哪一期」，**不是它什麼時候公開**。
直接拿來用＝在資料還沒公告的那天就假裝知道了＝偷看答案。

| 資料 | 所屬期間 | 最晚公告 | 回測裡可以用的日期 |
|---|---|---|---|
| 月營收 | 某月 | **次月 10 日前** | 次月 10 日（保守就用 11 日之後的第一個交易日） |
| 季報（Q1–Q3） | 季底 | **季底 ＋ 45 天**（約 5/15、8/14、11/14） | 公告截止日之後 |
| 年報（Q4） | 12 月底 | **隔年 3 月底** | 3 月底之後 |

- 雪鴞的 `月_營收` 索引是字串（例：`'2026-M07'`），不是日期；要自己換成「可用日」再對齊價格。
- 不確定公告日 → **用法定截止日**，寧可晚一點，不能早一天。

### 沒有雪鴞？

使用者有自己的 CSV 也可以：把路徑寫進 `DATA_SOURCE.md`，照 Step 0 檢查欄位、還原權值、有沒有下市公司。
第一堂送的 `factor-check`、`backtest-review` 裡都有 `load_local.py`， 已經會對應常見欄名，可以借用。

## 三、開工前三個必確認（Strategy Spec Confirmation）

**進入 Step 0 之前**，先把「要回測什麼」跟使用者對齊清楚。任何一項模糊就不能往下做。

### 1. 進場條件（Entry Rule）
- 完整的訊號定義（含所有濾網：趨勢、波動、產業、市值、流動性、籌碼）
- 標的範圍（單檔／一籃子／哪個股票池；雪鴞只有目前上市櫃的公司，要揭露存活者偏差）
- 進場時點（T 日收盤訊號成立 → T+1 開盤進場；⛔ 禁用「當根收盤進場」）

### 2. 出場條件（Exit Rule）
**所有出場路徑都要列**，至少回答：
- **停損**：固定％？ATR 倍數？跌破某條均線？
- **停利**：固定％？ATR 倍數？突破前高？還是不停利、靠時間或反向訊號出場？
- **時間出場**：持有 N 天強制出場？
- **訊號反轉**：反向訊號出現就出？
- **同一根 K 棒同時碰到停損與停利**：假設先碰哪個（保守＝假設先碰停損）
- **跳空穿越停損／停利**：用開盤價成交還是停損價？（保守＝用開盤價，反映真實滑價）

### 3. OHLC 進出場時點（Bar-level Execution）

**回測一律用 OHLC 日 K（或更高頻）跑**。OHLC 只給四個價格，每種出場都要明定成交價：

| 情境 | 用什麼價成交 | 理由 |
|---|---|---|
| **進場** | **下一根 K 棒的開盤價** | T 日收盤才確認訊號，實盤要等 T+1 開盤；用 T 收盤進場＝偷看未來 |
| **出場：用到盤後資訊**（法人籌碼、財報、用收盤價算的指標反轉） | **下一根日 K 的開盤價** | 跟進場對稱，訊號要等收盤才算得出來 |
| **出場：只看價量、盤中就能判斷**（停損停利掛單、跌破某價即出） | **盤中碰到就出**（用日 K 的最高／最低判斷有沒有碰到） | 實盤可以掛條件單，盤中碰到就成交 |
| **同一根 K 棒停損與停利同時觸發** | **假設先碰停損**（保守） | OHLC 還原不出盤中順序 |
| **跳空穿越停損／停利** | **用開盤價成交，不是停損／停利價** | 真實滑價 |
| **回測結束還有部位** | **最後一根收盤強制出場** | 避免未平倉部位汙染績效 |

> **必問的一句話**：「你的出場條件**有沒有用到盤後才知道的資訊**？」
> - 有 → 出場必須用 T+1 開盤
> - 沒有（只看最高／最低／即時價）→ 可以盤中碰到就出

**紅燈症狀**（規格沒對齊就開跑＝偷雞）：
- ❌ 假設寫「站上 60 日線進場」，沒寫在什麼時點、用什麼價成交
- ❌ 出場只寫「停損 -7%」，沒分「盤中碰到」還是「收盤確認」
- ❌ 用「今天的法人買賣超」當訊號，卻用今天收盤價進場（偷看未來）
- ❌ 沒過濾一字漲停／一字跌停（見第 4 點）

### 3-bis. 定期換股／因子輪動：訊號看收盤、進場隔天開盤（紅線）

**任何「每月／每週固定換股」的策略，都必須是：第 K 個換股日「收盤」算訊號 → 「下一個交易日開盤」進場與換股，報酬用開盤到開盤（open-to-open）計算。**
不准用「同一根 K 棒收盤算訊號、又用同一個收盤價成交」（same-bar）—— 你要等收盤後才知道訊號，不可能用那個收盤價買到。

| 做法 | 對不對 | 說明 |
|---|---|---|
| 訊號＝第 K 日收盤；進場＝第 K 日收盤（same-bar） | ❌ 隱性偷看未來 | 等收盤才算得出訊號，卻假設用那個收盤價成交 |
| 訊號＝第 K 日收盤；進場＝第 K+1 日開盤 | ✅ 正確 | 實盤就是收盤後跑訊號、隔天開盤掛單 |
| 報酬＝收盤到收盤 | ❌ | 只在 same-bar 假設下成立 |
| 報酬＝開盤到開盤（`adj_Open` 對 `adj_Open`） | ✅ 正確 | 進出場都在「訊號日的隔天開盤」，前後對稱 |

**用雪鴞月 K 的寫法**（月 K 每一根的 Open＝那個月第一個交易日的開盤）：

```python
close = px.pivot(index="date", columns="symbol", values="close")  # 月底還原收盤
opn   = px.pivot(index="date", columns="symbol", values="open")   # 該月第一天還原開盤
score = my_factor(close)          # 第 K 個月底收盤算分數（只能用到這一列以前的資料）
entry = opn.shift(-1)             # 下個月第一天開盤進場
exit_ = opn.shift(-2)             # 再下個月第一天開盤換股出場
fwd_ret = exit_ / entry - 1       # 這一列＝「用這個月底的訊號」實際拿到的報酬
```

- 這一天的落差通常只吃掉一點點報酬（隔夜跳空），對月頻策略影響小，但**不做就是偷雞、實盤對不上**。
- 只有還原收盤、沒有還原開盤的資料源：要嘛補開盤價，要嘛退而用「T+1 收盤」並**明說這是近似**。

**真實案例**：有一個因子輪動回測，第一版就是「收盤算訊號、又用同一個收盤價成交」，後來才改成隔天開盤進場。這種錯**不會報錯、數字看起來也很正常**，只有對著規則一條一條檢查才抓得到。

### 3-ter. 因子同分必須「同分同組」＋ 分組崩組後嚴禁寫死組號（雙紅線）

**紅線 A：任何因子分組（五分位、十分位、前 N 名），同分的股票必須落在同一組。**
pandas 用 `rank(method="average")` 再切組，或直接 `qcut` 數值；**絕對禁止 `rank(method="first")`** —— 那是「位置序」，資料通常按股票代號排，等於同分時代號小的優先入選，是有方向的系統性偏誤（台股＝傳產老公司優先）。

**紅線 B：取分組報酬時，嚴禁寫死組號（`grp[1] - grp[5]` 這種）。**
大量同分會讓 `qcut(duplicates="drop")` 的邊界重疊，當月只切出 3–4 組，而且 `labels=False` 會把標籤**重新編號成 1..k** —— 最強組永遠是 1，但最弱組變成 3 或 4。寫死「第 1 組減第 5 組」會把這些月份**整月默默丟掉**（不報錯、變 NaN、下游 `fillna(0)` 又變成假的 0）。
正確寫法：**先統一因子方向為「分數越大越好」**（越小越好的因子先乘 −1）。`qcut(labels=False)` 的標籤 0 是數值最小那組，所以逐月取「標籤最大＝最強組」減「標籤最小＝最弱組」（按標籤排序後 `groupby("date").last()` 減 `.first()`，至少 2 組才算）。**任何分組方法改動後，都要檢查報酬表的 NaN 月數有沒有暴增。**

| 做法 | 對不對 | 說明 |
|---|---|---|
| `rank(method="first")` 後切組 | ❌ 代號序偏誤 | 同分被資料順序硬拆 |
| `rank(method="average")` 後切組 | ✅ 同分同組 | 組大小每月浮動，學術標準做法 |
| `pd.qcut(值, N, duplicates="drop")` | ✅ 同分同組 | 直接按值切 |
| `grp[1] - grp[N]` 寫死組號 | ❌ 崩組月被丟 | 第 N 組可能不存在 → 整月 NaN |
| 逐月 `first()／last()` 取兩端 | ✅ 防崩組 | 不管切出幾組都拿得到兩端 |
| 同分時用市值當第二排序鍵 | ⚠️ 要明說 | 指數公司的做法，但會把規模效應混進因子 |

**高風險因子類型**（天生大量同分，必查）：比值封頂型（例：離 52 週高點的比例，封頂在 1.0）、整數評分型（0–9 分的財務評分）、群組共用值型（產業動能＝同產業同分）、無動作歸零型（整月沒買賣的籌碼因子＝0 分一大團）。

**紅旗症狀**：(a) 某因子報酬異常亮眼，而且分數有一大團同分 → 先查分組怎麼處理同分；(b) 某因子 12 個月報酬「剛好等於 0.0000」→ 幾乎一定是 NaN 被 `fillna(0)` 的指紋，去查有沒有月份被丟。

**真實案例**：一個「貼近 52 週高點」因子，某個月有幾百檔同分封頂在 1.0。改成同分同組之後，最強組的報酬少了幾個百分點 —— 偏誤不大，但方向固定，一定要修。另一個籌碼因子在硬寫組號的版本裡，歷史上大部分的月份都被默默丟掉，最後顯示成一個「剛好 0.0000」的假紅燈 —— 這個 bug 是另一個獨立檢查的 AI 抓到的。

### 4. 漲跌停／流動性過濾（台股紅線）

**台股漲跌停 ±10%／日（2015-06-01 起）。一字漲停＝整天買不到，一字跌停＝整天賣不掉。**
回測寫「成交了」是假成交，這比偷看未來還隱蔽 —— 錯不在訊號邏輯，而在「成交模型」。

| 情境 | 實盤真實情況 | 回測必須這樣處理 |
|---|---|---|
| **一字漲停**（開＝高＝低＝收，碰到 +10%） | 全天沒人賣 → **整天買不到** | 跳過這筆進場、延到 T+2 開盤；T+2 還漲停就繼續延，累計 N 天還鎖死就放棄這個訊號 |
| **一字跌停**（開＝高＝低＝收，碰到 -10%） | 全天沒人買 → **整天賣不掉** | 停損／停利出場無法成交 → 延到下一個有量的日子，實際出場價可能比停損價更差 |
| **盤中漲停（有量、不是一字）** | 有可能買到一部分 | 多加 1–2% 滑價，或限制部位上限 |
| **盤中跌停（有量、不是一字）** | 有可能賣到一部分 | 同樣多加滑價 |
| **流動性不足**（日均量 < 1000 張） | 大單會把價格打歪 | 設最小日均成交量門檻（雪鴞的量本來就是「張」，直接比） |

**回測程式必寫的判別式**（⛔ 用**原始價** `raw_*`，不要用還原價）：

```python
# ⚠️ 不要用「昨收 × 1.10 四捨五入」去比：台股漲停價要按跳動單位（最小報價單位）往下取，
#    例：昨收 101.3 → 漲停價是 111.0，不是 111.43。直接用漲跌幅判斷比較穩：
prev_close = df["raw_close"].shift(1)
chg = df["raw_close"] / prev_close - 1

flat = (df["raw_open"] == df["raw_high"]) & (df["raw_high"] == df["raw_low"]) & (df["raw_low"] == df["raw_close"])
is_limit_up_locked = flat & (chg >= 0.095)     # 一字漲停：整天一個價，而且漲了約 10%
is_limit_down_locked = flat & (chg <= -0.095)  # 一字跌停
# 除權息當天、新股上市前幾天（無漲跌幅限制）會有例外，遇到可疑的日子要抽查

# 進場
if is_limit_up_locked.iloc[entry_day]:
    entry_day += 1
    if entry_day - signal_day > MAX_WAIT_DAYS:
        skip_this_signal()

# 出場（停損／停利碰到了，但跌停鎖死）
if hit_stop_loss and is_limit_down_locked.iloc[exit_day]:
    exit_day += 1
    actual_exit_price = next_day_open  # 不是停損價，是隔天開盤價
```

**最常踩的策略**：飆股、漲停選股 —— 回測「找隔天會漲停的股票買進」年化 100% 以上，實盤一張都買不到。
**期貨**：台指期沒有一般意義的漲跌停，主要陷阱是「跳空＋流動性瞬間抽乾」，回測程式仍要留滑價彈性。

欄位：`symbol`、`n_trades`、`win_rate`、`total_pnl`、`pct_of_total_pnl`、`avg_pnl`、`max_dd_per_symbol`、`profit_factor`。
**警戒線**：單檔 `pct_of_total_pnl > 50%` → 🔴 集中度過高，報告必須點名。

### 四-4、肥尾檢查（Fat-tail）

單筆損益的分布不能假設是常態分布。

1. **單筆損益直方圖**（附常態分布疊圖對照）
2. **峰度（Kurtosis）**：≈ 3 🟢／5–10 🟡 中度肥尾／> 10 🔴 嚴重依賴極端事件
3. **偏度（Skewness）**：強正偏＝少數大賺撐起（趨勢策略常見，可接受）；強負偏＝多數小賺＋少數大虧（黑天鵝風險）
4. **前 5／前 10 筆占總損益**：前 5 筆 < 30% 🟢／30–50% 🟡／> 50% 🔴（拿掉那 5 筆就垮）
5. **單筆最大虧損 ÷ 平均虧損**：< 3 🟢／3–5 🟡／> 5 🔴
6. **VaR／CVaR**（單筆損益的 95%、99% 風險值）

### 四-5、時間集中性（Time Concentration）

1. **月報酬熱力圖**（`scripts/plot_charts.py` 已含）
2. **逐年統計**：每年筆數、勝率、損益、當年最大回撤 —— 80% 以上損益來自單一年 → 🔴 環境依賴
3. **最長水下期**（從前高跌下來到回到前高的最長時間）：< 3 個月 🟢／3–6 個月 🟡／> 6 個月 🔴
4. **空手期占比**：< 30% 可能過度交易；> 90% 訊號太稀，交易次數通常也少到沒有統計意義
5. **行情拆解**：切成多頭／空頭／盤整，至少在兩種行情都正報酬才算穩健

## 五、訊號品質評估（發牌統計）—— 排序主軸，先於資金層回測

### 兩層評估架構（一定要分開講）

| 層 | 量什麼 | 主要看 | 會被什麼汙染 |
|---|---|---|---|
| **發牌層（訊號品質）** | 每一筆訊號本身的品質 | **每筆期望超額報酬**（統一出場、扣成本、減大盤）＋勝率＋風報比（平均賺 ÷ 平均賠）＋一年幾個訊號 | 幾乎不受汙染 —— 這是策略的「牌」 |
| 資金層（組合績效） | 加上資金規則後的整體 | 五指標燈號（⛔ Sharpe 與 Sortino 並列） | 容量上限、選股順序、時機運氣、資金閒置 |

**鐵則**：排序與取捨先看發牌層，資金層當「執行效率驗證」。
資金層 ≈ 每筆品質 × 一年訊號量 × 容量利用率 —— 三個要拆開看，不能只看總分。

**真實案例**：一整族訊號在資金層回測裡很亮眼，拆開看發牌層，每筆品質其實很普通 —— 亮眼的部分是剛好搭上某段行情的時機運氣。

### 發牌統計標準流程

1. 所有候選訊號**統一配同一種出場**（例：跌破 20 日線隔天開盤出場，最長持有 60 天）—— 出場不同就不是同一把尺
2. 每個候選算：每筆期望超額、勝率、風報比、一年訊號量、訓練期（IS）與驗證期（OOS）分開列
   ⛔ **訓練期為負 → 一票否決**，驗證期再好看都是運氣
3. 加一欄「一年 alpha 供給」＝每筆期望 × 一年訊號量
4. **事件型訊號**要展示多個持有天數：T+1、T+5、T+10、T+20、T+40、T+60 —— 只看一個天數可能是挑出來的

### 五個防偽工具（按需使用）

| 工具 | 做法 | 抓什麼 |
|---|---|---|
| **單一訊號裸奔榜** | 每個原子訊號單獨進場、同一把尺量 | 找出「發動機」（單獨就有用）與「濾網」（單獨沒用，但能提純發動機） |
| **聯集保底（OR）** | 整族變體任一觸發就算訊號，量品質 | 榜首跟聯集的差距＝挑參數挑出來的水分 |
| **逐年牌品** | 按訊號年份分組、逐年看每筆期望與勝率 | 品質是常態，還是靠一兩個大年？最差那年多深？ |
| **逐筆蒙地卡羅** | 單筆池有放回重抽 5,000 次 | 消除「時機先後剛好」的運氣；輸出輸給大盤的機率 |
| **兩把尺對齊** | 海選用的中間指標排名 vs 最後落袋報酬排名 | 兩把尺的排名可能差很多 —— 海選被刷掉的，要用最後那把尺再審一次 |

### 質 × 量法則（發牌層 → 資金層要過四關）

1. **每筆品質**（基本功）
2. **訊號量夠不夠餵飽資金**：質高量少會餓死 —— 一年訊號太少，資金大部分時間閒置，資金層反而墊底。反過來，容量有限時質＞量
3. **好牌是不是都在買不到量的小型股**：用流動性分層重驗（全部 vs 日成交額夠大的那一層）
4. **訊號在時間上均不均勻**：一窩蜂出現的好訊號，滿倉時會被大量丟掉、稀疏時資金空轉。驗法：用逐筆重建每天的持倉數，看滿倉時間比例

- 多個策略搶同一池資金幾乎必輸；分開資金並行，才有分散的價值（相關性 < 0.8 時值得並行）
- 挑戰者發牌品質贏了、資金層卻輸 → 按四關逐一檢查，不要直接下「品質是假的」結論

### 回測窗口

**主評估窗口建議＝近 5 年**：行情一直在變，太久以前的市場結構不一定適用。

| 窗口 | 角色 | 用法 |
|---|---|---|
| **近 4–5 年** | **主評估** | 五指標燈號、每筆期望、所有對照表的主欄 |
| 長樣本（10 年以上，資料允許才跑） | 結構健全度對照（**不當否決依據**） | 只回答：有沒有失控的一年？最深回撤多深？爛年會不會連續？ |

⛔ **雪鴞的限制**：日 K 只有約 4 年 → 日頻策略主窗口就是這 4 年，報告要寫明「近 4 年」；
每月／每週換股的策略改用月 K／週 K，可以把長樣本拉到 2012 年之後。

配套紀律：
- 主窗口的交易樣本仍要 ≥ 200 筆，不夠就加長窗口或標註「樣本不足，僅供參考」
- 4–5 年通常只涵蓋一種行情結構 → 必配「逐年牌品」與逐筆蒙地卡羅
- 報告誠實揭露：「主數字為近 X 年，該期間行情特徵為 Y」

**違規症狀**：
- ❌ 只交資金層燈號表，沒有發牌層統計
- ❌ 用資金層排名選策略，沒檢查發牌層排名是否一致
- ❌ 「訓練期為負、驗證期很好」的候選沒被否決

## 六、開發流程（七步驟）

```
Step 0 資料檢查 → Step 1 假設 → Step 2 單因子驗證 → Step 3 回測引擎驗證
→ Step 4 參數 → Step 5 組合與濾網 → Step 6 穩健性
→ （收尾）Step 7 資金管理 → Step 8 交付前檢查
```

### Step 0：資料完整性檢查（最優先、永不跳過）
任何量化對話的第一件事。讀 `DATA_SOURCE.md` 確認資料在哪，再照 **`step0-data-triage.md`** 檢查。

### Step 1：假設形成
- 用一句話說清楚優勢：「當 X 發生時，Y 的機率比較高」
- 找文獻或實證支持（可以上網查）
- 確認資料拿得到（雪鴞有沒有這個欄位？頻率夠不夠？公告日是哪天？）

### Step 2：單因子驗證（最重要）
- **每個因子單獨驗證**，確認它自己就有用 —— 選股型因子直接交給 `factor-check`
- 參數用網格測試（grid search）掃一輪
- 記錄五指標＋勝率／PF／交易次數（`scripts/calc_metrics.py`）
- **不合格的因子直接丟掉**，不要想「組合起來也許會好」

### Step 3：回測引擎驗證
寫策略邏輯之前，先用 § 七的「回測引擎檢查清單」驗一遍。

### Step 4：參數優化
- **停損停利優先於訊號參數** —— 影響更大
- 找「一片高原」而不是「一根尖峰」：參數 ±20% 之後績效還穩不穩？
- 期貨類策略用 ATR 倍數設停損停利是常見做法

### Step 5：組合與濾網
- AND 邏輯（兩個訊號都確認才進場）通常比加權合成好
- 濾網的目的是「排除危險環境」，不是「只做安全環境」
- 負面濾網（不做 X）比正面濾網（只做 Y）實用
- 做多和做空可能需要完全不同的訊號與參數

### Step 6：穩健性驗證（完整版）
IS/OOS 四配置＋WFA 三配置＋滾動四檢驗＋蒙地卡羅，**詳見 `robustness-validation.md`**。
基本版至少要做一件：把期間切成前後兩半，後半段還有沒有效？

### Step 7：資金管理（讀附件 `money-management.md`）
Step 6 過了、進入交付前：
- 讀本資料夾的 `money-management.md`，照裡面的方法做（已內建，不用另外安裝）
- 用 `trades.csv` 跑模型對照（完整版＝12 模型 × 5,000 次模擬 × 200 筆）
- 產出表格：每個模型的中位數年化、中位數回撤、最壞 10% 回撤、爆倉機率
- 依使用者「可以忍受的回撤」挑 1–2 個模型說明
- ⛔ **禁用** 馬丁格爾（虧了就加倍）
- 股票動能／因子類策略：組合波動度目標（M12）是業界常見做法

### Step 8：交付前檢查
- 基本版：§ 四-1 的六項都有、`trades.csv` 跟權益曲線對得上、五條紅線都做了
- 完整版：跑一遍 `word-delivery.md` § 7 的 A–F 檢查清單
- `tv-chart` 互動圖要能離線打開；單一商品的進出場點要跟 `trades.csv` 一致
- 任一項沒過 → 不能說「完成了」。「以為做完」＝沒做完。

## 七、回測引擎檢查清單

每次寫新的回測程式都跑一次：

| 常見 bug | 怎麼檢查 | 怎麼修 |
|---|---|---|
| 偷看未來（Lookahead） | 訊號用 T 日資料，但那筆資料 T 日收盤後才公布 | 進場改 T+1 開盤 |
| 停損只看收盤 | 盤中跌破停損，收盤又拉回來 | 用日 K 的最高／最低判斷 |
| 夜盤波動被忽略 | 期貨有夜盤，只看日盤會低估風險 | 合併日盤＋夜盤的最高／最低 |
| 停損用固定點數 | 價位變化大時比例不一致 | 改用 ATR 倍數或百分比 |
| 權益曲線不連續 | 空手期間沒記錄 | 每天都記 |
| 成本低估 | 只算手續費、沒算滑價 | 成本 ×1.5 倍 |
| **資料含週末／假日列** | `df[df["date"].dt.weekday >= 5]` 應該是空的；週一的滾動訊號莫名變 0 ＝嫌疑 | 特徵函式開頭 `df = df[df["date"].dt.weekday < 5]`；見 step0 § 7 |
| **一字漲停買到／一字跌停賣到** | 開＝高＝低＝收＋碰到漲跌停價的那天，有沒有被當成可成交 | 進場延後、停損延後用隔天開盤；見 § 三-4 |
| **流動性不足的股票混進來** | 日均量 < 1000 張的有沒有排除 | 股票池加 `volume_lots.rolling(20).mean() >= 1000`（雪鴞的量是張） |
| **用財報／月營收的「所屬期間」當日期** | 月營收在月底那天就被用了？ | 改用公告日或法定截止日（見 § 二-B） |

必做清單：
- [ ] 進場用 T+1 開盤（不是 T 收盤）
- [ ] 停損停利用最高／最低判斷
- [ ] 有夜盤就合併日盤＋夜盤
- [ ] 停損觸發用精確停損價出場（跳空例外，見七-A）
- [ ] 權益曲線每天都有記錄
- [ ] 成本含手續費＋稅＋滑價，×1.5
- [ ] 持倉中不開新倉（除非策略允許加碼）
- [ ] 結束時若有持倉，強制出場

### 七-A、同一根 K 棒的價格事件優先順序

OHLC 還原不出盤中真實順序，一律採**保守假設**：

| 情境 | 假設 | 理由 |
|---|---|---|
| 同一根同時碰到停損與停利 | **假設先碰停損** | 不能挑對自己有利的順序 |
| 進場當根就碰到停損／停利 | **當根就出場** | T+1 開盤進場後，要用同一根的最高／最低檢查 |
| 跳空穿越停損價 | **用開盤價成交**，不是停損價 | 實際成交不到停損價 |
| 跳空穿越停利價 | **用開盤價成交**（比停利價好） | 有利方向也要如實反映 |

### 七-B、出場價分流表

| 出場類型 | 成交價 | 說明 |
|---|---|---|
| 停損／停利觸發 | 精確停損／停利價 | 掛單性質（跳空例外見七-A） |
| 訊號反轉出場 | **T+1 開盤** | 跟進場對稱 |
| 時間到期出場 | T+N 收盤或 T+N+1 開盤 | 選一種，全程一致 |
| 回測結束強制出場 | 最後一根收盤 | 避免未平倉汙染績效 |

### 七-C、進出場時序鐵則

1. **進場**：T 日收盤訊號成立 → **T+1 開盤**進場（日內策略：T 分鐘收盤 → T+1 分鐘開盤）
2. **當根收盤進場＝偷看未來**，禁止
3. **訊號用的資料公布時間必須早於進場時間**（例：法人資料盤後才公布，不能在當天收盤進場）
4. **出場邏輯要跟進場對稱**

## 八、停損停利方法比較

| 方法 | 適用 | 優點 | 缺點 |
|---|---|---|---|
| 固定點數 | 短期、價位穩定的標的 | 簡單 | 長期會失效 |
| 固定價格％ | 股票 | 自動適應價位 | 不適應波動變化 |
| 固定資金％ | — | — | 受槓桿影響大，不推薦 |
| **ATR 倍數** | **期貨、外匯、波動差異大的標的** | **自動適應波動** | 要多算 ATR |

常見起點：用進場時的 ATR，停損 1.0–2.0 倍、停利 2.0–4.0 倍，再用 Step 4 掃參數確認是高原。

## 九、多空不對稱原則

長期多頭的市場裡（台股多數年份如此）：

| | 做多 | 做空 |
|---|---|---|
| 訊號要求 | 雙重確認（兩個條件同時成立） | 更多重確認 |
| 環境濾網 | 輕度 | 嚴格（趨勢轉弱＋波動放大＋結構確認） |
| 停損 | 較緊 | 較寬 |
| 預期交易頻率 | 較多 | 很少 |
| 合理的 Sharpe | 較高 | 能維持正的就不錯 |

**經驗法則**：做空比較好的環境，通常是「剛開始轉弱、還沒恐慌到底」；已經恐慌到底時做空，常常反而虧最多。
（這是方向性的觀察，要用在自己的策略上，一樣得自己回測驗證。）

## 十、實戰踩坑速查表

| 坑 | 症狀 | 解法 |
|---|---|---|
| 因子疊加無效 | 組合後 Sharpe 比單因子還低 | 回 Step 2 逐一驗證 |
| 回測好得不真實 | Sharpe > 2.0 或勝率 > 70% | 先查有沒有偷看未來 |
| 停損一直被掃 | 停損占出場 > 50% | 放寬停損（ATR 倍數加大） |
| 樣本外崩潰 | 驗證期 Sharpe < 訓練期的 30% | 過擬合，減少參數 |
| 做空全面虧損 | 空方 Sharpe < 0 | 不要在多頭市場硬做空 |
| 夜盤跳空虧大 | 單筆虧損遠大於預期停損 | 合併夜盤最高／最低 |
| 交易太少 | 一年 < 20 次 | 放寬訊號、降門檻，或拉長期間／擴大股票池 |
| 交易太多 | 一年 > 200 次 | 成本可能吃掉 alpha |
| 雪鴞日 K 不夠長 | 想看 10 年，只拿到 4 年 | 策略改月／週頻，用月 K／週 K |
| 流動性門檻失效 | 均量門檻設 1000 卻濾掉幾乎所有股票（或完全沒濾） | 檢查量的單位是張還是股 |
