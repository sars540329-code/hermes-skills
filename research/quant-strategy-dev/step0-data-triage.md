# Step 0：資料完整性檢查（Data Triage）

> **任何量化對話的第一件事**。不管使用者是要開發新策略、來問「這個回測好不好」、還是貼了一張回測報告截圖，
> **都先檢查手上的資料夠不夠支撐後面的分析**。資料不全就繼續動手＝白工。

## 0. 先讀 `DATA_SOURCE.md`

- 還是「尚未設定」→ 問使用者資料在哪（雪鴞的 `.env` 位置、裝雪鴞的 python，或自己的 CSV 資料夾），問到就寫回去
- 已設定 → 照上面寫的位置拿資料，不要再問一次
- ⛔ 只記路徑，不記帳號密碼；不要打開 `.env` 念給使用者聽

## 1. 常見來源與常見缺口

| 來源 | 通常會有 | 通常缺什麼 |
|---|---|---|
| **雪鴞（snowyowl）** | 全市場日 K（約 4 年）、週／月 K（約 2012 年起）、還原價、市值、成交額 | 已下市公司（存活者偏差）、日 K 的長歷史 |
| **XQ 等看盤軟體的回測** | 年化、勝率、MDD、交易次數、權益曲線、月報酬、交易明細（多半可匯出 CSV） | Sharpe／Sortino／Calmar、滾動 12 個月、IS/OOS、WFA、蒙地卡羅、參數敏感度、分行情績效 |
| **TradingView 策略** | 權益曲線、淨利、PF、MDD | Sharpe；交易明細要手動匯出 |
| **使用者口述／截圖** | 只有幾個數字 | 幾乎全部 |
| **Python 自己寫的回測** | 看程式而定 | 看程式而定 |

## 2. 清點使用者提供了什麼

收到資料後立刻條列：

```
✅ 已提供：[逐項列出]
❌ 未提供：
   - 策略原始碼／明確進出場條件
   - 完整時間範圍
   - 手續費／滑價設定
   - 起始資金／張數或口數邏輯
   - 交易明細 CSV
   - 日權益曲線
```

## 3. 向使用者索取的統一清單

```markdown
為了把這份資料補齊成可以交付的完整分析，請提供：

**A. 策略本體（三選一，越上面越好）**
- [ ] 完整策略原始碼（XScript／Python，可以 1:1 重現）
- [ ] 文字描述的進出場條件（可以用，但要反覆確認）
- [ ] 至少一份交易明細 CSV（可以反推部分邏輯）

**B. 回測設定**
- [ ] 時間範圍（例：2022-01-01 ～ 2026-09-30）
- [ ] 標的（個股代號／股票池／期貨商品）
- [ ] 起始資金、張數或口數邏輯
- [ ] 手續費、滑價設定
- [ ] 停損停利規則

**C. 原始資料（可選，但最好有）**
- [ ] 交易明細 CSV（時間、方向、進出價、損益）
- [ ] 日權益曲線 CSV

**D. 目的**
- [ ] 準備實盤？ → 要走完整版
- [ ] 要對外發表？ → 要走完整版
- [ ] 只是驗證想法？ → 基本版就好
```

**如果使用者只給截圖或幾個數字**，明說：「光靠這些算不出 Sharpe、WFA、蒙地卡羅，請至少給交易明細 CSV 或策略條件」，**不要硬算**。

## 5. 紅旗清單（看到立刻停下來問）

| 紅旗 | 為什麼可疑 | 必問 |
|---|---|---|
| Sharpe > 2.0 但交易次數 < 30 | 統計上不顯著 | 「回測多長？幾筆？」 |
| 勝率 > 70% | 可能偷看未來 | 「訊號資料什麼時候拿得到？T 日還是 T+1 進場？」 |
| 手續費／滑價＝0 | 嚴重低估實盤成本 | 「確認有扣成本嗎？」 |
| MDD 淺於 -3% 而年化 > 30% | 幾乎不可能 | 「有凹單？加碼攤平？參數過度貼合？」 |
| 只有整段回測、沒有分段 | 無法判斷穩健性 | 索取 IS/OOS 或重跑 |
| 單一標的但參數很多 | 過擬合 | 數參數個數、要求樣本外驗證 |
| 用到當根收盤之後才有的資料 | 偷看未來 | 「有沒有用到 T 之後的資料？」 |
| 財報／月營收直接用「所屬期間」對齊價格 | 偷看未來 | 「這筆資料實際是哪一天公告的？」 |

## 6. XScript → Python 對照（使用者給 XQ 腳本時）

| XScript | Python／pandas |
|---|---|
| `close, open, high, low` | `df["close"]`、`df["open"]`… |
| `average(close, 20)` | `df["close"].rolling(20).mean()` |
| `atr(10)` | 自己寫 ATR |
| `setposition(1 / -1 / 0)` | 多／空／出場訊號 |
| `crossover(a, b)` | `(a > b) & (a.shift(1) <= b.shift(1))` |

語法不確定時，上網查 XQ 官方的 XScript 說明，不要猜。

## 7. 資料欄位健康檢查（尤其是 API 類資料）

拿到任何外部資料（雪鴞、yfinance、其他 API…），**動手算訊號前**先跑這幾件事，否則滾動視窗類的訊號會被汙染而不自知。

### 7.1 日期只能有交易日

```python
df["date"] = pd.to_datetime(df["date"])
weekends = df[df["date"].dt.weekday >= 5]
assert len(weekends) == 0, f"資料含週末列：{weekends['date'].unique()}"
```

有些 API 會在週六日回傳一列「沿用週五的值」的填充資料，造成：
- `pct_change`／`diff` 在週末＝0
- 「連續 K 天」這類滾動計算被 0 打斷
- 每個週一的訊號都被吃掉 → 實際進場次數系統性少於設計

**修法**：特徵函式開頭直接 `df = df[df["date"].dt.weekday < 5]`。

### 7.2 同一天不能有重複列（除非有其他維度，例如代號）

```python
dup = df.groupby(["date", "symbol"]).size()
assert (dup == 1).all(), "同一天同一檔出現重複列"
```

### 7.3 實際檔數要看過

**抓取顯示成功，不等於真的有抓到資料。** 每張表用之前先看每天有幾檔：

```python
n = df.groupby("date")["symbol"].nunique()
print(n.describe())   # 某些日子突然只剩個位數 → 資料有斷層
```

### 7.4 假日與連假前後

比對交易所行事曆；某週少於 5 個交易日要回頭確認是不是真的放假。

### 7.5 量的單位

雪鴞的成交量是「張」、很多其他來源是「股」。**混用前先確認單位**，不然流動性門檻會差 1000 倍。

### 7.6 還原權值

用來算報酬的價格要是**還原價**（雪鴞：`adj_*`），不然除權息那天會出現假跌。
判斷漲跌停用**原始價**。

## 8. Step 0 什麼時候算過關

**以下任一成立，才進入 Step 1**：
- 可交付度評估 ≥ 70%
- 關鍵缺口已經向使用者索取，對方答應補（或明確說不補）
- 紅旗都釐清了

**千萬不要跳過 Step 0 直接動手算。**
